可以。**你这张图很适合做成 3D 场景：用清晰的几何模型建立空间，再通过手绘笔触材质、彩色光照和风格化植物，把它做出水粉厚涂的感觉。**

我建议采用这条路线：

**Unity URP ＋ 手绘笔触贴图 ＋ 自定义彩色光照 Shader ＋ 植物色块造型 ＋ 少量后期。**

先把模型和材质阶段的画感做好，再用后期统一色彩。下面以你这张“白色悬浮方块＋彩色树木”的图为例，讲具体怎么落地。

## 一、先把画面拆成几个能实现的部分

| 图里的视觉效果 | Unity 中的实现方式 |
|---|---|
| 错落、悬挑的白色方块 | 简单几何模型，清楚的平面法线，必要时加小倒角 |
| 白色表面上的斜刷、色块 | 手绘底色贴图＋笔触遮罩，控制颜色变化 |
| 暖白亮面、蓝紫暗面 | 自定义光照色带，让受光程度对应指定颜色 |
| 玫红、黄绿的植物 | 简化叶簇造型、手绘植物贴图、统一的树冠受光 |
| 墙面上的斑驳树影 | 植物真实投影，必要时用 Light Cookie 补充 |
| 明亮的青蓝天空 | 手绘天空盒或天球材质 |
| 整体通透、鲜艳的感觉 | 色调映射、少量调色、适度的远景雾 |

**其中最值得优先做的是“白色方块材质”。** 它在画面里占比最大，做好它，就能很快判断整套风格是否成立。

## 二、模型保持清楚，笔触做在表面上

### 1. 方块模型怎么做

针对这张图，我会这样处理：

- 保留方块之间的大小差异、悬挑关系，以及露出天空的缝隙。
- 方块各个面的法线保持清楚，让顶面、侧面、底面能形成明确的明暗分区。
- 边缘可以加很小的倒角，用来接一点光；倒角宽度不要破坏方块的利落轮廓。
- 表面的绘画痕迹主要通过颜色变化实现，凹凸变化保持克制。

这张图里，方块的形体很规整，颜料笔触却比较自由。**把“规整的形体”和“松动的表面颜色”同时保留下来，效果就会接近。**

### 2. 笔触贴图建议分成三层

| 层级 | 画什么 | 作用 |
|---|---|---|
| 大色块 | 大片暖白、淡蓝、淡紫的变化 | 打破一个面的均匀颜色 |
| 中等笔触 | 斜刷、横刷、边缘不齐的覆盖色块 | 建立主要的水粉厚涂质感 |
| 小笔触 | 少量细碎色点、干刷边缘 | 增加局部丰富度 |

最关键的是中等尺寸笔触。它们要有**方向、长短和疏密**。例如，建筑正面可以以斜向笔触为主，底面则用较宽的横向色块。

建议先准备两类贴图：

- **颜色贴图：**提供暖白、淡粉、淡蓝等颜料变化。
- **灰度笔触遮罩：**告诉 Shader，哪里稍微偏亮、哪里偏冷、哪里出现一块刷痕。

如果第一版使用普通 Lit 材质，我会把 `Metallic` 设为 `0`，`Smoothness` 从 `0～0.15` 这个较低范围开始试，先让表面呈现柔和、粉质的观感。这是针对这张图的起步建议。

### 3. 笔触要固定在哪里？

**建筑优先用 UV 或物体空间贴图。** 这样镜头移动时，笔触会稳定地附着在方块表面。

静态大型建筑也可以用 `Triplanar`，即从三个方向投射贴图，减少手工展开 UV 的工作。Unity 的 Triplanar 节点支持调整投射空间、尺寸和混合程度；它会对贴图进行三个方向的采样。对于规则方块，普通 UV 往往已经足够。[docs.unity.cn](https://docs.unity.cn/Packages/com.unity.shadergraph@17.0/manual/Triplanar-Node.html?utm_source=chatgpt.com)

会移动或旋转的方块更适合 UV 或物体空间。如果使用固定世界坐标采样，物体移动时会出现“物体穿过纹理”的感觉。

## 三、核心 Shader：让光照决定“用什么颜色画”

这是整套方案最重要的一部分。

对这张图，我会给不同材质设计不同的明暗颜色：

| 材质 | 受光区域 | 过渡区域 | 阴影区域 |
|---|---|---|---|
| 白色建筑 | 暖白、浅奶油黄 | 淡青、淡紫灰 | 蓝紫、青灰 |
| 玫红树冠 | 珊瑚粉、亮粉红 | 玫红 | 紫红、偏蓝的深红 |
| 黄绿植物 | 柠檬黄绿 | 鲜绿 | 青绿 |

这样，阴影也能保留鲜明的色彩。每类材质有自己的配色关系，整张图会更丰富。

### 1. 用一条“光照色带”控制颜色

可以画一张横向的渐变贴图，例如 `256×1`：

- 左端放阴影色。
- 中间放过渡色。
- 右端放受光色。

Shader 根据表面朝向光源的程度，在色带上取颜色。这里建议做成**几个主要色区之间的柔和过渡**，再用笔触遮罩扰动过渡的位置，形成手绘感。

下面是核心逻辑示意，**不是完整、可直接粘贴运行的 Unity Shader**：

```hlsl
// normalWS：世界空间法线
// lightDirWS：朝向主光源的方向
// brushMask：0～1 的笔触遮罩
// shadowVisibility：真实阴影可见度，0=遮挡，1=未遮挡

float ndotl = saturate(dot(normalWS, lightDirWS));

// 笔触让局部受光颜色产生小幅变化
float brushShift = (brushMask - 0.5) * brushStrength;

// 阴影参与决定色带上的取色位置
float lightAmount = saturate(ndotl + brushShift);
lightAmount *= shadowVisibility;

// 自定义函数：在你画好的色带中取颜色
float3 color = SamplePainterlyRamp(lightAmount);

// 再叠加幅度较小的颜料冷暖变化
color *= pigmentVariation;
```

这套逻辑对应的画面效果是：

**方块朝向光源的面出现暖白，背光面进入蓝紫区域，笔触遮罩让每个平面的颜色有局部变化。**

完全处于阴影中的表面，还可以通过最后的 `pigmentVariation` 保留刷痕和冷暖变化。

### 2. 一定要接入真实投影

`N·L` 只能表达一个面朝向太阳还是背向太阳。树叶、树枝，以及上方方块投下来的阴影，需要另外读取主光的阴影信息。

Unity 的 URP 提供了相应接口，例如带阴影坐标的 `GetMainLight(...)` 会返回 `shadowAttenuation`。实际工程中，建议从官方模板取得这部分数据，让它处理对应的阴影坐标和变体。[Unity Editor](https://docs.unity.com/en-us/engine/6000.0/manual/materials-and-shaders/shaders/writing-custom-shaders-urp/use-built-in-shader-methods/shadows?utm_source=chatgpt.com)

这里有个非常关键的处理：

**让阴影控制“在色带哪里取色”，就可以保留蓝紫色暗部。** 如果最后再把整块颜色直接乘以一个降到零的阴影系数，暗部就会变成黑色。

### 3. 在 Shader Graph 里怎么开始？

如果使用 **Unity 6.3 或之后的版本**，可以从 Package Manager 导入 Shader Graph 的官方 **Custom Lighting** 示例。Unity 6.3 专门增加了支持这种工作流的 Unlit 设置和示例模板。[Unity Editor](https://docs.unity.com/en-us/engine/6000.3/manual/whats-new/unity63?utm_source=chatgpt.com)

我建议从它的 **Lit URP** 示例开始，保留需要的光照功能，再修改漫反射的颜色处理。官方的 Lit Toon 示例默认使用硬分段光照，你可以参考其结构，把分段改成适合这张图的柔和色带。[docs.unity.cn](https://docs.unity.cn/Packages/com.unity.shadergraph@17.3/manual/Shader-Graph-Sample-Custom-Lighting-Lighting-Models.html?utm_source=chatgpt.com)

使用官方这套 Lighting Model 子图时，有几个明确的配置要求：

- 使用 **Forward 或 Forward+** 渲染路径。
- 将计算完成的 `Lit` 输出接到 **Unlit Master Stack 的 Base Color**。
- 开启 `Keep Lighting Variants`。
- 按示例要求关闭 `Default Decal Blending` 和 `Default SSAO`，避免与示例内部的处理重复。[docs.unity.cn](https://docs.unity.cn/Packages/com.unity.shadergraph@17.3/manual/Shader-Graph-Sample-Custom-Lighting.html?utm_source=chatgpt.com)

这里的 **Unlit 是最终颜色的输出方式，光照和阴影已经在 Graph 内部算好了**。如果把已经计算完光照的颜色再送入普通 Lit 的 Base Color，它还会继续经过默认照明，容易破坏你设计好的明暗颜色。

Unity 6.0 等较早版本也可以通过 Custom Function 或 HLSL 做自定义光照，只是接入细节需要按对应版本处理。[Unity Editor](https://docs.unity.com/en-us/engine/6000.0/manual/lighting-overview/lighting/custom-lighting/introduction?utm_source=chatgpt.com)

## 四、植物要先做成“大色团”，再补叶片

你这张图里的植物，最有辨识度的是右上角的大块玫红树冠，以及穿插在建筑之间的黄绿色枝叶。

我会按这个顺序制作：

### 先确定树冠轮廓

用几个大小不同的叶簇构成树冠，先看远处是否形成好看的色块。树冠内部要有疏密，避免平均分布成一团球。

### 再补轮廓上的叶片

在外轮廓和局部空隙放少量带透明裁剪的手绘叶簇卡片。每张卡片可以包含一小簇叶子，让它在游戏视距下读起来像几笔颜色。

### 整理植物的受光

建筑需要清楚的平面法线；植物则可以让叶簇的光照法线适当向树冠外侧发散，让树冠形成比较连贯的亮面和暗面。

配色也按叶簇组织：一簇偏粉，一簇偏紫，一簇受光偏珊瑚色，保持大面积颜色之间的关系。

### 检查树影

叶片卡片的透明裁剪、投影轮廓和风动画需要一致。这样才能避免出现叶子看起来是镂空的，墙上却投出矩形影子的情况。

**对这张场景，树叶投到白墙上的斑驳阴影，是非常值得花时间打磨的部分。**

## 五、光照和天空：建立明亮的冷暖关系

### 主光用一盏明确的太阳光

第一版先固定太阳方向，用斜射光让方块产生清楚的亮面、侧面和底面。

我会从这样的关系开始调：

- 主光：轻微偏暖。
- 建筑受光面：暖白。
- 建筑阴影：蓝紫、青灰。
- 植物亮面：更偏黄、更明亮。
- 天空：高明度的青蓝。

如果采用前面那个简化的自定义 Shader，环境光、间接光等需要明确进入你的计算，或者由设计好的暗部颜色来承担视觉作用。保留官方完整光照模板后再修改，通常更便于继续支持这些功能。

### 斑驳日光可以用 Cookie 加强

真实植物的阴影负责空间关系；想要进一步控制墙面上的光斑，可以给 Directional Light 配一张树冠空隙图案的 Cookie。

URP 的方向光支持 2D Cookie，并可调整 `Cookie Size` 和 `Cookie Offset`。这很适合控制斑驳光斑的大小、位置和缓慢移动。[Unity Editor](https://docs.unity.com/en-us/engine/6000.0/manual/lighting-overview/lighting/light-component?utm_source=chatgpt.com)

Cookie 是灯光投射的图案。使用自定义光照时，要确认 Shader 确实采样了 Cookie；只读取阴影衰减，并不代表已经处理了它。

### 天空直接做出手绘形状

可以制作一张青蓝天空贴图，用较大的白色刷痕画云，再用天空盒或天球显示。

这张图的天空占比不小，云的形状和笔触尺度会直接影响整体画感。远景如果需要雾，我会用很淡的青蓝色，只让远处的建筑稍微融入天空。

## 六、后期用来统一画面，先保持轻量

### 1. 色调映射先从 Neutral 开始

针对这张鲜亮配色，我建议先试 **Neutral Tonemapping**。Unity 官方说明，Neutral 对色相和饱和度的影响较小；ACES 会带来更强对比，并改变一定的色相与饱和度。这里选择 Neutral，是为了方便保住你设计好的青蓝、玫红和淡紫。[Unity Editor](https://docs.unity.com/en-us/engine/6000.0/manual/post-processing-and-full-screen-effects/urp/effect-list/tonemapping?utm_source=chatgpt.com)

其余效果可以按下面的目标调整：

| 效果 | 针对这张图的建议 |
|---|---|
| 曝光与对比 | 保留白色方块上的淡色笔触和树影 |
| 饱和度 | 在材质配色完成后，小幅调整整体关系 |
| Bloom | 只保留轻微的亮部光晕 |
| SSAO | 用少量接触暗部交代方块接缝和植物根部 |
| 景深 | 游戏视角下保持克制，避免把精心制作的色块模糊掉 |

SSAO 可以控制强度、半径，以及它在直接受光区域的可见程度。对白色建筑，我会先关闭或设得很弱，等整体光色成立后再增加接触层次。[Unity Editor](https://docs.unity.com/en-us/engine/6000.0/manual/lighting-overview/lighting/shadows-in-urp/post-processing-ssao/ssao-renderer-feature-reference?utm_source=chatgpt.com)

### 2. 更强的绘画后期可以放到第二阶段

如果材质已经有画感，还想把细碎细节归并成更大的色块，可以研究 **Anisotropic Kuwahara，方向性 Kuwahara 滤波**。这类方法会沿局部图像方向进行抽象处理，同时保留形状边界，可以产生绘画式的色块效果。[kyprianidis.com](https://www.kyprianidis.com/p/pg2009/index.html?utm_source=chatgpt.com)

在 URP 中，可以通过 **Fullscreen Shader Graph＋Full Screen Pass Renderer Feature** 接入自定义全屏效果。Unity 提供的是接入方式，具体的绘画滤波仍需要实现。[Unity Editor](https://docs.unity.com/en-us/engine/6000.0/manual/post-processing-and-full-screen-effects/urp/custom-post-processing/custom-effect-low-code?utm_source=chatgpt.com)

这一步需要检查实际运动画面：建筑与天空的交界、细树枝、移动角色和 UI，是否仍然清楚稳定。主体笔触已经附着在物体上时，全屏效果只需较弱的强度。

## 七、实际制作时，我建议按这个顺序推进

**先做一个很小的美术验证场景：两三个方块、一棵树、一盏太阳光、一个相机。**

1. **搭形体和配色。**  
   调出暖白建筑、青蓝天空、玫红树冠、黄绿小植被之间的关系。

2. **完成一个方块材质。**  
   加入大色块和中等尺寸笔触，检查不同面的笔触方向与尺度。

3. **加入彩色光照和真实阴影。**  
   让受光面进入暖白，背光与遮挡区域进入蓝紫；让树叶真正投影到方块上。

4. **移动相机做检查。**  
   看笔触是否稳定附着、植物是否有体积、近看是否出现明显重复纹理。若方块会运动，也要移动方块检查贴图。

5. **扩展成完整场景。**  
   再增加建筑、树木、天空细节和最后的调色。面向移动设备时，重点观察叶片重叠、实时阴影和全屏滤波的 GPU 开销。

**对你这张图，第一阶段最明确的目标就是：一个方块在真实光照下，能同时呈现暖白亮面、蓝紫暗面、清楚的斑驳树影，以及稳定附着的刷痕。** 这个小样做好后，就有了一套可以复用到整片建筑上的美术基础。
