# 《Kiva》关卡自动生成器详细设计

本设计面向关卡策划和 Unity 开发。策划给出本关可用的场景模块、角色可携带的道具，可选的过关操作顺序，以及空间形态。生成器据此制作一张地图，给出一段能在游戏中重放的通关操作，并检查玩家能否用另一条路线完成目标。

**核心设计决策：先构造一种值得玩的解法，按解法反推空间，再从成品地图独立寻找第二解。** 生成和验证分开，是因为设计者安排了一条路线，只能说明有意让玩家这么走。下文描述拟实现的编辑器工具；文末列出了可复用的现有代码。

## 1. 策划需要提供什么

| 输入 | 含义 | 示例 |
|---|---|---|
| 场景模块 | 本关的搭建白名单。生成器决定用量、位置、朝向和表面分配。 | 固定砖、活动砖、白面、岩石面、金属面、水晶面 |
| 角色道具 | 玩家在本关可以使用的全部道具。允许某件道具，意味着验证器要考虑它的每一种合法用法。 | 风扇、弹弹菇、纸翼 |
| 过关操作顺序，可留空 | 指定关键动作及其先后关系。留空时，由 AI 根据前两项提出动作组合。 | 风扇推砖到断口 → 从该砖顶弹起 → 展开纸翼转向目标台 |

| 空间形态 | 新建请求默认封闭，可选择开放。 | 有顶棚的房间和门洞、露天平台 |

只填前两项即可按默认封闭形态生成。首版建议默认列入的道具开局全部可用，允许道具清单为空。策划若需要途中发放，可以在道具项内指定补给时机。白名单允许生成器取子集，某种机制是否必须使用由操作要求表达。**缺少依赖要指出具体冲突**：例如指定“用风扇推活动砖”，却只允许固定砖。单纯允许风扇且没有活动砖仍是合法输入，风扇也能推动玩家。

出生点和通关目标由工具自动生成。首版采用一个目标出口，并沿用游戏的实际完成条件：角色在出口范围内站稳即触发结算。玩家原有的行走、跳跃、碰撞、重试同样参与验证。基础移动始终可用；地形所需的砖和面仍须来自本关白名单。

## 2. 怎样算“只有一种路线”

一条路线由**跨过哪些关键空间、借助什么机制、该机制作用于哪个对象**决定。每张图中，断口两侧、高台、起跳砖、可安装面和目标都有稳定标识。回放时可以据此记下“由断口西侧借活动砖 A 顶部的弹弹菇越墙，到达东侧高台”。

| 两次通关的差异 | 如何判定 |
|---|---|
| 登上同一块砖时多走了两步，起跳点偏了半格 | 同一路线。落点和操作时刻有容错。 |
| 一人先贴菇再推砖，一人先推砖再贴菇，最终都借就位的同一块砖起跳 | 同一路线。除非策划明确要求准备动作也有先后。 |
| 一人从砖顶弹过墙，另一人用侧墙的菇横向弹过去 | 两条路线。起跳对象和跨越方式改变。 |
| 两人都用了风扇和弹弹菇，其中一人用风直接吹过断口，随后在目标旁补踩了一次菇 | 两条路线。用道具的次数和顺序相似，真正把玩家送过断口的机制不同。 |

策划用自然语言写顺序时，编辑器将它转换为可见的关键事件，绑定动作、对象、结果和先后关系。例如“风扇推砖到止挡”要求风扇推动**同一块砖**抵达止挡，“借砖顶起跳”要求这块砖实际承载弹射。若写了“趁砖还在移动时起跳”，就额外绑定起跳时砖的速度条件。如果两种解释会生成不同的谜题，编辑器指出有歧义的词，让策划选定含义。只指定一部分动作时，生成器可以补全路线；补全后的整条路线仍要检查唯一性。

**事件怎样匹配。** 回放和搜索共用一套事件定义。一次跨越记录出发区、抵达区、起跳宿主，以及实际参与跨越的机制和对象。例如连续弹射接滑翔记为「砖 A 顶部弹射 → 空中滑翔 → 高台 B」，同一时段的联合受力按机制集合记录。安装、等待、微调通常只更新世界状态；当它们是策划点名的步骤时，也记录目标与先后关系。回到相同状态、没有获得资源或改变后续跨越、也未推进指定步骤的绕行可被消去。遇到因果不明的复合动作，保留所有可能解释并报告不确定性。只有两段回放的关键跨越、对象绑定和被要求的先后关系都等价，才合并为同一解法。

## 3. 一个新模块如何接进来

模块目录按稳定 ID 查找定义。策划使用中文名称，生成器、游戏和验证器使用同一个 ID。一个定义需要交付以下信息。

| 需要描述的内容 | 以风扇为例 |
|---|---|
| 怎样放进关卡或交给角色 | 作为道具授予玩家；装在可瞄到、底座放得下且没有重叠装置的白面上。 |
| 在游戏里产生什么变化 | 沿安装面法线对风场内无遮挡的受力物体施力。移动宿主上的装置随宿主移动，风扇不推动自己的宿主。 |
| 生成器怎样用它设计谜题 | 可以提供“推砖至止挡”或“借风跨越”两种动作。给出安装方向、距离、遮挡和目标落区的约束。 |
| 验证器怎样发现其他用法 | 暴露受力范围和适用对象，考虑玩家、活动砖、重新安装及其与其他机制的组合。实现尚未覆盖的情况记入验证报告。 |

对“会受力的物体”“允许安装的表面”等共同条件建模，新砖只要符合条件，就能和已有风扇交互。具有特殊规则的模块需要实现自己的行为。例如新增**冰面**，它改变接触时的摩擦和可滑达范围，即使玩家没有主动操作也会生效。接入时要同时更新运行时的接触行为和验证器的移动范围；若还想让 AI 主动设计滑行谜题，再提供相应的动作描述。未知规则只能用于探索候选，不能支撑唯一性结论。

解析单关白名单时，同时限制搭建器、道具发放、操作规划和路线搜索。检查最终布局实际包含的材质、实例、发放记录和启用的行为。这样，注册冰面后，旧关卡仍然只启用各自原有的规则。若调整的是全局移动规则，受影响的旧验证报告应按规则版本失效。

## 4. 从动作到空间

1. **确定候选解法。** 指定顺序时，把它编译为带前置条件和结果的动作。留空时，向 AI 提供本关的模块、道具、动作及参数范围，由它组合出若干候选。每个动作的对象都必须能在布局中实例化，前一步的结果必须满足后一步的条件。未知动作或违反白名单的候选在这里淘汰。固定候选后，后续求解和复现不依赖再次调用 AI。
2. **从终点反推布局。** 例如要做“推砖 → 弹起 → 滑翔”，先求能滑入目标台的出发高度和速度，再求能获得这组起始条件的弹射台范围，接着反推活动砖的终点、导槽、止挡和风扇安装面。最后放置出生点，检查道具能否瞄准、砖能否登上、装置是否有足够的安装面积。用现有砖格拼出地形，在满足约束的范围内改变高差、间距、朝向。无可用布局时回退到上一步换参数或候选。
3. **用游戏规则跑通。** 在临时关卡中驱动正常的移动、瞄准、放置和物理步进，记录输入及关键事件。只有实际触发结算，且事件满足指定步骤、对象绑定、因果关系及候选路线时，才得到正解。若玩家意外被风直接吹到目标，保留这段反例，返回布局阶段。回放用角色实际能执行的输入衔接各段，包含进门前的速度和出门后的落点。
4. **独立搜索替代路线。** 验证器从最终几何、全部可用动作和真实出生状态出发，也要探索候选解法没有提到的白面、平台和道具。反例若能重放，报告指出它绕过了哪次跨越、用了哪块面；生成器可据此收窄白面、移动平台或调整落差，再从头验证。
5. **选择可玩的结果。** 在同一验证等级内优先选择连续动作确实衔接、可预判落点、有操作余量的候选。例如“跃入井底门 → 从墙门高速飞出 → 空中转向滑翔”可以验证出门速度是否被下一段真正利用。对瞄点、起跳时机和移动方向施加小幅扰动，记录仍可成功的范围。扰动幅度由试玩校准，报告保留测量值。

## 5. 唯一性怎样验证

**先证实有解，再排查其他解。** 实际物理回放提供第一条证据。为找第二解，验证器把可站立区域、空中可达范围、安装面、活动砖和机关状态组成搜索图。状态至少包含玩家的位置与速度范围、接触状态、已获道具、装置所在面及位置范围、砖的位置与运动范围、检查点和抵达出口的状态。连续机制在运动**途中**也能被利用，只验证砖的起点和终点会漏掉中途弹射。

搜索时同时保存“到这里为止发生了哪些关键跨越”。两条路即使落在同一个平台，只要抵达方式不同，就要分开继续验证。独立从最终碰撞几何提取可站立面和可达区域，包括装饰形成的落脚点；预期路线上的命名区域只用于解释结果。尝试常规跳跃、借风、搬动或重装装置、从旧区域折返，以及从已激活检查点重试。重试按游戏规则清空装置、复位活动砖、重新计算装备。一次无收益的绕圈不会产生新解；若重试带来了新位置、装备或完成机会，就必须继续搜索。

搜索的问题是**能否用另一条路线触发游戏结算**。可用队列遍历“世界状态 + 路线匹配进度”，为每次转移保留前驱和操作。匹配器标记首次分歧，搜索继续沿该分支寻找结算；这样，违反指定顺序仍能通关的操作也会暴露出来。命中后沿前驱重建并重放反例。只有当两个状态的合并仍覆盖它们所有可能的后继和路线差异时，才可用合并结果支持严格结论。

| 报告结果 | 判定依据 | 编辑器如何处理 |
|---|---|---|
| 唯一性已验证（注明规则范围） | 有符合要求的正解回放。对本图启用的所有规则，搜索模型完整或保守地覆盖每一次真实状态转移及其可能的路线事件（含重试和结算）；穷尽模型后，所有可结算路径均与正解等价。穷尽一组离散采样点本身不满足覆盖条件。 | 显示适用的规则版本、覆盖依据和正解回放。 |
| 可通关，唯一性未验证 | 有成功回放，但只做了采样、某机制缺少覆盖、搜索超额，或保守模型给出的疑似捷径仍无法排除。 | 允许预览，标出具体缺口，不计入通过唯一性验收的关卡。 |
| 存在第二解 | 找到关键路线不同、且在游戏中能重放的通关操作。 | 同时展示两条路线，定位首次分歧的物件和动作。 |
| 未生成 | 输入冲突、已证明给定范围无解，或在预算内未能构造可重放的正解。 | 分别说明冲突项、无解范围或耗尽的预算。预算耗尽不能推出无解。 |

首版可从**单块活动砖、直槽、少量白面、单目标**开始建立可验证的布局集合。直槽若仍允许砖翻滚、玩家推挤、装置装在砖侧，就必须覆盖这些运动，或通过实际几何和表面配置消除它们。固定物理步长和随机种子有利于复现，但多次成功回放只能验证这些操作确实可行。自由门位、移动门和空中改装等组合，在覆盖其连续位置与速度前，一律使用采样结论。

## 6. 在 Unity 项目中的落点

| 工程位置 | 已有能力 | 拟对接方式 |
|---|---|---|
| 关卡资源和几何 | `WorkshopLevel` 保存砖区、逐面白色标记、活动砖、装备和出口。`WorkshopLayout` 组合模块预设，`WorkshopGeometry` 从模块实例构建碰撞及可安装面。 | 首版导出新的关卡资源，沿用现有搭建器。固定砖区有覆盖顺序，验证时读取展开后的实际表面。新机制超出现有字段时，为关卡增加按模块 ID 读取的实例参数，并保留旧资源的读取方式。 |
| 道具和角色 | `WorkshopPlacement` 有四个安装位；`FerryPuzzle` 用枚举和固定数量切换工具；HUD 也有相同假设。纸翼由角色移动代码处理。 | 首版为已有道具做 ID 映射。引入新道具时统一从目录取得装备、输入槽和显示信息；分别支持安装型工具和装备型能力。复用现有的面命中、安装、穿门及受力逻辑。 |
| 回放和结算 | `FerryPuzzle` 管会话、补给、重试及出口落地判定。 | 提取可由真人输入或回放驱动的操作入口，沿用同一物理与结算路径。每次验证用独立临时关卡状态，避免一次回放影响下次搜索或玩家存档。 |
| 编辑器和导出 | `WorkshopLevel` 的 Inspector 可生成可编辑的关卡预设，出口范围可在场景视图中查看。 | 增加编辑器生成入口。展示四项输入、候选地图、预期动作、正解或反例回放和报告。保存新图时分配独立关卡 ID 与稳定出口 ID。大厅的「剧情」入口直接载入 Gameplay。 |

复现一次生成要记录输入、已选定的结构化动作、随机种子、规则与生成器版本、物理设置、实际地图和回放输入。将报告绑定到地图内容和规则版本；手工移动一块砖、调整摩擦或改装置尺寸后，都要重新验证。试玩可以直接打开已保存的地图，无须依赖 AI 再次给出相同回答。

## 7. 实现顺序与验收

| 阶段 | 实现内容 | 能判定成败的验收案例 |
|---|---|---|
| 一、验证器先行 | 在两张小型手工图上实现实际输入回放、关键事件记录和反例搜索。 | 基准图允许“风推砖 → 砖顶弹射”；给变体侧墙增加一块足以装菇的白面后，验证器能重放侧向弹射捷径，并指出分歧。基准图的报告等级取决于覆盖证据。 |
| 二、指定解法生成 | 从模块目录读取本关白名单，按给定动作链反推布局，导出 `WorkshopLevel`。 | 用同一顺序生成不同布局并分别回放。禁用弹弹菇时，指定弹射的输入得到依赖冲突；没有指定弹射的输入仍可尝试其他解法。 |
| 三、AI 自选解法 | 留空第三项时生成候选动作链，校验因果关系，按连续性和操作余量筛选。 | 对同一组模块得到可解释的候选，回放能复现选中动作。AI 虚构的道具或无法衔接的动作在导出前被发现。 |
| 四、接入新机制 | 以新增冰面检验被动机制的注册、单关启用和报告失效。 | 禁用冰面的关卡沿用原规则。启用冰面的测试图能滑到旧规则下不可达的平台；缺少对应验证模型时，报告明确标注唯一性未验证。 |

另用三个边界样例验收：允许但预期解中没用的道具确实可以制造第二解；检查点重试确实可以改变通关路线；搜索超时仍保留已知正解与未覆盖范围。这三例决定工具能否向策划如实说明一张图已经验证到了哪一步。

### 已可试玩的推砖对照实验

在 Unity 编辑器中打开 **纸坊 → 推砖弹射基准关 → 对照实验**。选「播放对照图原解」看风推砖到止挡，选「播放侧墙捷径示例」看另一条路线，也可以选「试玩并录制对照图」自己走一次。

两张图的出生点、地形、装备和出口相同。对照图把起步侧台内壁的一格岩石面换成了白面。实测有以下结果。

| 地图 | 已在新会话中重放的通关路线 |
|---|---|
| 基准图 | 风推砖到止挡后借菇起跳。另一条路线直接斜向助跑，借初始位置的砖顶弹射到高台，再走到出口。 |
| 侧墙对照图 | 原解仍然成立。新增白面上的风扇能横向推动角色，角色随后从原位砖顶的菇起跳。把这段输入放回基准图，墙面安装失效，在同一录制时限内没有结算。 |

「搜索侧墙捷径」会从成品碰撞面的可安装位置生成候选，实际执行安装、助跑和跨越。发现候选后，它在独立关卡状态中重放，并把同一串输入送回基准图作对照。编辑器 Console 会显示装置作用位置、受力步、抵达出口步和结算结果。内置示例只用于演示。搜索也采样了侧墙贴菇的走法，目前验证成功的侧墙路线使用风扇；这些采样的覆盖范围不足以证明唯一性。

### 已接入编辑器的指定解法生成

在 Unity 顶部选择 **纸坊 → 关卡生成器 → 按指定解法生成**，会先打开配置窗口。勾选允许的场景模块、玩家可用的道具，再输入过关操作顺序。也可以点动作按钮组合顺序。第三项留空时，本地规划器从可用动作和前置条件中搜索最多三个动作的组合，并显示将要验证的路线。选择「空间形态」后，点击 **按以上输入生成地图** 才开始搭建。相同输入和种子可从报告再次提交。

模块可选固定砖、活动砖、白面、岩石面、金属面、水晶面。出生点和出口需要固定砖和至少一种表面。角色可同时携带时空枪、风扇、弹弹菇、纸翼，也可以全部不选。指定顺序使用窗口列出的动作，可用箭头或“然后”分隔。编辑器会解释缺少的模块或道具，并指出无法识别的动作。自动规划使用本地符号搜索，当前文本输入支持动作词表及其常用说法。

例如，选择固定砖和岩石面、道具留空，输入“跳过断口 → 跳过断口”，会搭出两段独立跨越。改为固定砖和白面、携带弹弹菇和纸翼，输入“踩弹弹菇起跳 → 展开纸翼滑翔”，会生成可安装的起跳面和更宽的断口。风扇推砖后接砖顶弹射会另外构造导槽、活动砖和止挡。每次最多尝试八张图。

开放与封闭都支持分段转向。多段路线从前一块落脚台接出直行、左转或右转的走台。安装面、砖槽、起跳边和验证角色的移动方向跟随同一段旋转。封闭模式沿路线围出房间，段间通过门洞衔接，弹射房留出更高的顶棚，深坑底板位于跌落重试线以下。围墙按所选岩石、金属或水晶面分配材质。只允许白面时，围墙也参与道具安装和捷径采样。旧报告按原来的开放布局播放和复现。

多段路线在八张候选的总预算内，优先比较两张已通过玩家视角复验的图。报告列出关键动作之间达到 45° 的视线变化、各段移动方向的变化、最长连续直行距离，以及起跳前从角色眼睛到落台近边缘的视线检查。穿门造成的自动转头单独跳过。候选先按已发现的捷径、受遮挡的落台数量排序，再比较转向和直行长度。短关保留自然走法。

一次生成只进入一次播放模式。编辑器底部的进度任务显示当前候选和验证步骤。要中止，可以按顶部的停止播放按钮，或选 **纸坊 → 关卡生成器 → 取消生成**。中止后会返回原编辑场景，之前保存的报告仍可打开。

生成结束后，Inspector 会选中验证报告。从 **纸坊 → 关卡生成器 → 播放最近生成关正解** 或报告中的「播放生成关正解（玩家视角）」进入第一人称回放。角色会逐渐转头，在准星对稳安装面后点击。传送门的两次放置分别瞄准，跳跃、滑翔和穿门都由游戏自身处理。新关卡会在生成时录制这组操作，并从起点独立重放，确认按指定路线抵达出口、落地后保存。同版报告缺少玩家视角录像时，首次播放会准备并验证录像。旧版地图可直接试玩。结算规则或预设已变更时，点「用相同输入和种子重新生成」取得当前版本的报告和回放。

玩家视角优先播放录下的操作。碰撞使角色提前或延后抵达时，角色会按当前站位调整移动和瞄准，每次安装仍须命中记录中的同一道具目标，整段路线仍须通过原有的动作验收。要逐个物理步对照求解器最初的输入，可在报告中点「播放原始验证回放」。

点「试玩生成关」可以用键鼠操作。有反例的候选会同时保留正解和捷径。通过验证的配置地图保存为 `Assets/GeneratedLevels/Course-种子-批次/Level.asset`，同目录的 `Editor/Report.asset` 记录空间形态、模块、道具、指定顺序、实际采用的动作、候选和回放。通过 **纸坊 → 关卡生成器 → 查看上次生成报告** 可以重新打开。

验收使用实际游戏输入和独立的关卡实例。组合路线会检查每段的实际机制事件、抵达平台、抵达出口及落地结算，随后在新会话状态下重放输入，再逐段试走绕过指定动作的路线。单独的“推砖 → 砖顶弹射”另有专门的容错和捷径检查：至少助跑 0.50 米，首次落台净余量至少 0.20 米，测试前后各偏 0.12 米、左右各偏 2° 的四种组合，再分别朝出口和高台近角试五个原位起跳角度。这些测试的覆盖范围均不足以证明唯一性。

随项目附带的「推砖渡槽」使用种子 `17041`。第一张候选允许从原位砖顶直接弹上高台，第 213 个物理步就能结算。第二张的正解会跌落。第三张把高台近角从 X/Z 的 4.5/7.5 米移至 6.0/10.5 米，通过了验收。正解在第 8 步推砖、第 97 步弹射、第 198 步抵达出口、第 233 步结算。首次落台净余量为 1.18 米，四种扰动下最小为 0.72 米。原位捷径的十次尝试中，七次弹起后跌落，三次在预算内未触发弹射。参见[生成关卡](../Assets/GeneratedLevels/PushBounce-17041-93fa89e8/Level.asset)和[验证报告](../Assets/GeneratedLevels/PushBounce-17041-93fa89e8/Editor/Report.asset)。

另用种子 `17042` 运行同一套验收也通过了。它把高台近角放在 7.5/10.5 米处，玩家要再多跨过一格宽的空隙。

### 按精彩程度一键生成

在 Unity 顶部选 **纸坊 → 关卡生成器 → 按精彩程度生成**，再选一个档位，就会用新种子建图并验证。第一次默认封闭。想生成露天中庭，可以在「按指定解法生成」窗口把「空间形态」改为开放，快捷菜单会记住这个选择。窗口里的 **一键生成进阶关** 使用当前填写的种子和空间形态，道具和操作顺序由进阶档配置。

| 档位 | 玩家要完成的操作 |
|---|---|
| 标准 | 从下层工位布置双门，穿到上廊，再助跑跳过一格的排水缺口。上廊有五格宽，留出了调整站位的空间。 |
| 进阶 | 用风扇把活动砖推到止挡，在同一块砖顶装菇并弹起。对岸落台偏离弹射方向，玩家要展开纸翼转弯，落上四格宽的回廊，再沿廊返回入口对面的出口。 |
| 挑战 | 提前装菇并对准双门，出门后要在 1.2 秒内接上弹射。开翼后转向三格宽的上廊，最后还要跳过两格的断口。 |

首版以一座中庭为单位生成。下层工位与对岸的高廊共用基底，廊板下面有支墩和挡墙，外侧的柱列和檐梁标出出口方向。种子改变庭院尺寸、工位到落台的距离和整体朝向。生成器检查每块固定结构都经由接触面连到基底，并从出生点的眼睛高度检查通往出口和第一处工位的视线。[封闭进阶中庭的入口实景](visual-review/generated-atrium-advanced-entry.png)

每张候选先用实际角色输入完成指定动作、抵达出口，再检查捷径、操作偏差和玩家视角回放。标准档调整起跳位置与方向，进阶和挑战档调整开翼时机与飞行方向。两次轻微偏差都要能完成路线，进阶和挑战还要求两次明显偏差中至少有一次无法完成。玩家视角复验时，进阶档从弹射方向到空中速度方向至少偏转 12°，挑战档至少偏转 40°。每次最多尝试八张图，报告记录各项实测结果。

随项目附带一张种子为 `17041` 的封闭进阶中庭。选中它的 `Report.asset`，在 Inspector 点 **试玩生成关** 可自己操作，要复验历史样本，点 **用相同输入和种子重新生成**，随后可播放新报告里的正解。原报告记录的测试中，开翼晚 0.04 秒或 0.08 秒、同时偏转 2°，两次仍然通关。开翼晚 1.30 秒、分别往两侧偏转 24°，两次均未完成路线。[进阶中庭地图](../Assets/GeneratedLevels/Course-17041-2785d829/Level.asset) · [试玩与回放报告](../Assets/GeneratedLevels/Course-17041-2785d829/Editor/Report.asset)
