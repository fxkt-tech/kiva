# 跨层检查

## 使用时机

属性、技能、单位视图、输入命令或模拟事件改变时，检查完整数据流，不局限于发生编译错误的文件。

## Kiva 数据流

1. `src/client/content.rs` 注册定义并调用 `spawn_unit`。
2. `src/client/controls.rs` 收集有顺序的设备事件并提交模拟指令。
3. `src/simulation/` 在固定步处理规则，保存权威状态并发布结果。
4. `src/client/scene.rs` 插值和绘制，`src/client/ui.rs` 生成只读数据。
5. `src/client/web.rs` 桥接浏览器，`web/hud.js` 展示，`scripts/browser-*.cjs` 验证。

## 检查问题

- 修改的字段是定义、运行态、意图还是结果，唯一写入者在哪里？
- 构造、注册校验、效果执行、死亡/重生是否同步适配？
- 单位、固定步时序、显示帧插值、CSS 与 viewport 坐标是否混用？
- Rust 快照与 JS 字段、选择器、原生 HUD、三维范围指示是否全部接入？
- 无效命令是否保持原状态，暂停/失焦后是否会重复或遗留输入？
- 既有浏览器数值断言是否仍有意义，是否误删了能发现回归的检查？

## 验证

先用 `rg` 找齐使用者。规则测试走 `tests/simulation.rs` 的公开接口，交互/坐标/布局走现有浏览器辅助函数。
不要为了测试跨层结果而公开模拟运行态写权限，也不要在 JavaScript 补算规则。
