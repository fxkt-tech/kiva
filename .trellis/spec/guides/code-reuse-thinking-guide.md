# 复用检查

## 搜索后再扩展

使用 `rg` 查同类定义、计算和测试。先确定已有模块是否能承载新行为，再决定新增文件或接口。

## 已有复用点

- `spawn_unit`：所有单位构造和校验。
- `AbilityCatalog`：技能定义注册与合法组合校验。
- `actions.rs` 的技能提交点：消耗、冷却、效果统一提交。
- `NavigationMap`：移动、冲刺和弹丸共用的静态地图几何。
- `combat.rs`：统一伤害、死亡、重生，避免在每种效果内独立扣血。
- `GamePointer` 和 `web.rs`：统一游戏光标及坐标转换。
- `browser-support.cjs`：真实鼠标捕获下的点击、移动、世界投影和临时服务器。

## 接口检查

- 新增机制应把复杂规则集中在拥有它的模块，调用方提交意图并观察结果。
- 不因为未来可能有多个实现就先引入 trait、插件注册或第二套状态。
- 不在输入、相机、移动和伤害中复制按具体角色/技能 ID 判断的分支。
- 不用静态内容常量或 DOM 值代替模拟权威状态。
- 相同计算修复应只需修改一个实现；不同生命周期不应为了减少几行代码强行合并。

## 测试检查

验证可观察行为及失败时状态保持，不通过重复实现同一公式来证明它正确。
有意义的计算边界场景可以留在模块内，主要玩法场景仍通过公开模拟接口执行。
