# 战斗模块重构：技能数据化与系统拆分

状态：用户于 2026-11-12 要求处理架构分析的第 2 项。沿用上一个任务的方式：方案后直接实现。提交与推送未授权。

## Goal

让战斗模块符合“内容是数据、系统一件事”：加一个已有形态的技能只需加一行数据；每个系统和函数只做一步。**行为不变**。

## 现状依据

- `simulation/combat.rs` 1943 行：`prepare` 约 350 行（计时、选目标、联动窗口、推进动作、拉近监督、防御、换组、准入、开始动作、拉力），`advance` 约 435 行（玩家倒地复活、五类技能结算、普通敌人 AI）。
- 只有普攻有数据表（`MeleeProfile`）；技能的范围、伤害、控制、标记时间、窗口时长、冷却内联在 `match ActionKind` 分支和 `availability_for` 里，同一个数字（如 4.5、22、12）出现在多处。
- 既有回归：`combat_tests.rs` 37 个、`melee_chain_tests.rs` 16 个、Boss 16 个，以及客户端依赖战斗事件的测试。

## Requirements

| ID | 需求 |
|---|---|
| R01 | 技能的时长、冷却、施放距离、标记时间、伤害、控制、窗口时长、拉近参数集中在一张数据表，每个数字只出现一次 |
| R02 | `combat.rs` 拆为模块目录，按职责分文件；对 `simulation` 其余部分和客户端的公开接口不变 |
| R03 | `advance` 拆成“玩家动作结算”和“普通敌人”两个系统；耐力恢复与妹妹快照分开；减速计时独立；固定步内的先后顺序不变 |
| R04 | `prepare` 保持一个系统（循环内共享大量本步状态），但每一步是具名函数 |
| R05 | 事件的种类、顺序、`hit_index`、位置与半径不变；冷却、窗口、取消时序不变 |
| R06 | 不改 `Combatant` 的公开方法，不改客户端 |

## 不在范围

- 把 `Combatant` 拆成多个 ECS 组件：会改动客户端十几处查询，属于另一步。
- 新技能形态、数值调整、Boss 逻辑。
- 外部数据文件（RON/JSON）：数据表先以 Rust 常量存在。
