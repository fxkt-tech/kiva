# 第一版技术设计

状态：用户明确授权“开始实现吧”，本设计作为实施基线。已确认范围见 [PRD](prd.md)；首轮参数可调，行为契约保持不变。
D01 已确认：第一版接受有辨识度的临时妹妹模型和程序化武器，正式美术后续接入。

## 1. 玩法基线与操作

| 输入 | 第一版行为 |
|---|---|
| WASD／鼠标水平 | 沿用视角相对移动与水平转向，普通镜头构图不变 |
| Shift | 沿用按下闪避、长按衔接疾跑及既有无敌窗口 |
| C／空格 | 沿用蹲伏与滑铲、二段跳；空格按下立即请求跳跃 |
| 左键 | 当前武器组的哥哥近战普攻，按下一次只尝试一次 |
| 右键按下／持续／松开 | 拆招 → 防御 → 弹反；完整规则见第 3 节 |
| 中键 | 有锁定则解锁；无锁定则选择面前的有效敌人；不做自动补锁或 Q 切目标 |
| E／Q | 当前组的普通近战技／普通远程技；按下提交，立即给出起手或拒绝反馈，命中仍按前摇发生 |
| Tab | 尝试消费当前有效联动，一次前置条件最多一次联动 |
| 1／2 | 选择锤鸟／链斧弓；普通空闲时可换组，冷却保留，旧联动清理 |
| 滚轮 | 移除切换人格的产品行为，不重新映射为隐藏攻击或选组 |
| F2／F3／Esc | 保留敌人模式、哥哥身体外观、暂停入口 |

默认不锁定。未锁定时普攻按 Facing 检查前方范围，链斧 E 围绕哥哥执行；其他 E／Q 需要锁定。
候选筛选复用现有三维距离、胸口瞄准点和视线，选取评分沿用面朝优先／距离次之，完全同分以实体 ID 稳定排序。
锁定不自动转相机；施法可以朝承诺目标对齐动作，但不能把用户鼠标累计延迟到动作结束后补转。

## 2. 权威、模块与状态

沿用单 crate 和 client → gameplay → simulation；不引入技能脚本框架或网络协议。

| 位置 | 拟负责内容 |
|---|---|
| simulation/actions.rs | MotionState 的移动、支撑、跳跃、闪避、蹲伏；移出旧卸势窗口和战斗冷却 |
| simulation/combat.rs | 玩家战斗编排、目标、指令准入、命中应用、普通敌人推进；拆小内部函数，避免新增规则继续塞进一个 advance 分支 |
| simulation/defense.rs（新增） | 有序右键流程、拆招／防御／弹反窗口、冷却和只读 DefenseState |
| simulation/resources.rs（新增） | Stamina 的值、恢复等待和固定步恢复；不预埋烈阳／月光／怒气 |
| simulation/abilities.rs（新增） | 具名普通技和联动时间线、ComboWindow、链斧离手／拉近进度及只读动作快照 |
| simulation/weapons.rs | WeaponPair 数据、普攻与各技能的数值；规则保留具名实现，不做通用内容解释器 |
| simulation/boss.rs | Boss 决策、阶段和动作状态；通过共同命中结算处理来袭，通过自身唯一状态接受僵直 |
| simulation/physics.rs | motor 接收战斗移动限制和拉近目标速度，真实碰撞求解；发布运动快照 |
| gameplay/mod.rs | 装配生命 1000、耐力、逻辑妹妹，以及模式替换时的关联清理 |
| client/companion.rs（新增） | 妹妹显示根、出场／退场、独立骨骼动作和枪／弓挂点；无伤害权限 |
| client/combat.rs、animation.rs、camera.rs | 哥哥与妹妹武器表现、动作和两套联动镜头，均只读模拟 |
| client/controls.rs、web/input.js、client/web.rs | 原生／Web 输入适配、边沿一次消费和捕获边界 |
| client/hud.rs、web/hud.js、index.html、web/style.css | 两技能槽、耐力、锁定与联动的只读显示；不改变既有 16:9 外框 |

关键状态建议：

- WeaponPair 为 HammerMusket／ChainAxeBow；不再以 WeaponMode 决定玩家身份。挂点仍可使用“近战／远程握柄类型”，但它只是客户端几何约定。
- Combatant 持有当前组、显式目标、E／Q／普攻冷却、当前动作及联动窗口。不同组共用 E 槽与 Q 槽冷却，避免切换刷新。
- ActionRuntime 记录 action_id、kind、weapon_pair、target、elapsed、已经结算的标记。具名时间线是唯一射击／命中时钟。
- ComboWindow 记录 source_action_id、pair、original_target、condition 和截止时间，不能仅存一个“Tab 可用”布尔值。
- DefenseState 独占右键流程；Stamina 独占耐力。移动、战斗、资源各自维护自己的状态，不枚举所有状态的笛卡尔积。
- 妹妹的逻辑实体 Companion { owner: player } 在装配时创建，不含 Body／Health／MoveIntent，也不被敌人当作目标。技能信用归玩家，演出归属为妹妹。
- 战斗事件保留明确 actor，增加 source_owner／action_id／hit_index 或等价字段。妹妹射击 actor 是妹妹逻辑实体，受击事件 actor 是受击者；客户端不按中文状态猜归属。
- 联动快照供相机读取 camera_style、elapsed、原目标和最后有效瞄准点。表现不反向回调推进技能。

逻辑妹妹没有物理身体，因此不能直接塞进现有“所有 ActorView 都能查询 Body”的路径。
新增 CompanionView { owner, performer } 及其同步路径；复用骨骼采样和资产缓存，避免复制另一套权威动作时钟。

动作准入采用共同的只读 ActionAvailability，HUD 读取相同事实，模拟仍在消费指令时重新验证：

| 当前状态 | 移动 | 可以接受的主动动作 |
|---|---|---|
| 地面空闲／普通蹲伏 | 沿用现有速度 | 普攻、E／Q、有效 Tab、右键、跳跃／闪避、切组 |
| 普通腾空 | 沿用现有空中运动 | 剩余额度内二段跳、普通近战；地面技能与右键不接受 |
| 滑铲 | 沿用滑铲 | 沿用 C 起身和跳跃／闪避退出；拒绝新攻击和右键 |
| 拆招／防御／弹反 | 常速 0.35 倍，不疾跑 | 跳跃／闪避退出姿态；拒绝普攻、E／Q、Tab 和切组 |
| 普攻或普通技能执行 | 允许普通方向移动 | 第一版不做主动取消；拒绝新攻击、右键、跳跃／闪避、切组，只接受当前技能的有效 Tab 分支 |
| 联动执行 | 锤鸟停止主动移动，链斧弓由拉近控制 | 只处理锁定显示、暂停和外观／模式入口；拒绝其他主动动作 |
| 死亡 | 沿用物理落体，停止主动运动 | 不接受战斗输入；复活清掉排队指令 |

这张表是首轮操作限制建议，属于 P06 的审阅范围；若手感要求允许普通攻击取消，先改表再改调度和测试，不在实现中临时加隐藏例外。
同一步先处理取消／目标请求与允许的换组，再按 Tab → E → Q → 普攻尝试至多一次新起手；其余攻击指令消费后丢弃。

## 3. 右键、耐力与共同命中

### 3.1 右键状态流程

~~~mermaid
stateDiagram-v2
    [*] --> 空闲
    空闲 --> 拆招窗: 有效按下且拆招就绪
    空闲 --> 等待防御: 按下但拆招冷却中
    拆招窗 --> 空闲: 短按已松开且窗口结束
    拆招窗 --> 防御: 持续按住达到阈值且耐力足够
    等待防御 --> 防御: 持续按住达到阈值且耐力足够
    防御 --> 弹反窗: 有效松开且弹反就绪
    防御 --> 等待防御: 耐力不足
    等待防御 --> 防御: 仍按住且耐力恢复足够
    等待防御 --> 空闲: 松开
    弹反窗 --> 空闲: 窗口结束
~~~

候选参数：拆招窗 0.20s，进入防御阈值 0.20s，弹反窗 0.18s，拆招／弹反各自再触发冷却 0.65s。
边界使用半开时间区间，0.20s 起为防御，不同时享受拆招和持续防御。

- 短按松开后允许已启动的拆招窗口自然结束；不会变成弹反。完整按下／松开都发生在一次显示采样之间时也要保留这次拆招。
- 只有从有效防御状态物理松开，且弹反冷却就绪，才能开启弹反。失焦、Esc、pointercancel、死亡和 clear 都是取消，不能伪造成松开。
- 无效状态下按右键不启动窗口或冷却，也不排队到落地后执行；重新可操作时要求新按压。
- 拆招／弹反只处理符合正面阈值的有效来袭；两者免伤。拆招不附带僵直，弹反给攻击者建议 0.80s 僵直。
- 两者各自有冷却；拆招冷却中仍可通过持续按住进入普通防御；弹反冷却中松开仅退出防御，不补放。
- 三种防御状态均不能同时攻击。地面慢速移动允许，速度建议为常速 0.35 倍，不能疾跑。
- 跳跃／闪避可退出右键姿态；新按压不得在已起手技能或联动中插入。空中、滑铲、拉近、死亡不接受右键新起手。
- 普通蹲伏可拆招／防御，保留当前蹲伏与战斗共存的使用方式。
- 按住期间耐力不足，仅让有效防御失效；不新增击退、破防硬直或“三次上限”。安静后恢复足够耐力，可在仍按住时恢复防御。
- 右键长按防御本身不消耗耐力，不强制站着也持续扣耐力。

### 3.2 耐力

候选参数：上限 100，每次有效格挡消耗 20，安静 1.0s 后每秒恢复 15。

- 正面、有效防御、耐力 >= 本次消耗，才算格挡：扣一次耐力，生命承受原伤害的 50%；刚好扣到 0 的这一击仍成功。
- 耐力不足时，本次正常受伤，不部分抵扣耐力、不额外处罚；下一次是否能防御仍按当前值判断。
- 拆招／弹反／闪避不扣耐力；与下一版能量系统无耦合。
- 哥哥处于进攻动作（含妹妹技能和联动）时不恢复；动作结束后重新等待安静期。
- 真正到达受击结算的来袭，无论命中、格挡、拆招、弹反或闪避，均视为“受到攻击”，重置安静计时；挥空、隔墙攻击不重置。
- 持续按防御但无来袭不阻止恢复。暂停与 HitStop 不增加安静时间、不恢复耐力。
- 恢复在本固定步所有来袭处理之后运行；同一步受到攻击不会先恢复一截再格挡。
- 复活恢复满耐力；F2 切敌人模式保留当前耐力，避免用模式按钮补资源。

### 3.3 共同命中接口

攻击方保留自己的范围、前摇和空间检测；通过共同结算入口处理“已经满足空间命中条件”的候选。
建议计算接口为 resolve_hit(HitContext, DefenderSnapshot) -> HitOutcome，再由单一应用路径更新生命、耐力、控制效果和事件；具体 ECS 借用由实现阶段选择，不为它建立全局通用消息总线。

HitContext 至少包含 source、source_owner、target、action_id、hit_index、伤害、来源点、攻击性质及控制请求。
HitOutcome 至少区分 Invalid／Invulnerable／Dodged／Deflected／Blocked／Parried／Damaged。

判定顺序：

1. 拒绝死亡、目标移除、重复结算以及 Boss 转阶段／击败无敌。
2. 判定有效闪避无敌，再判定有效正面拆招、正面弹反、正面防御，最后普通命中。
3. 非伤害结果不产生伤害型控制；弹反单独请求攻击者僵直。成功伤害才施加技能的击飞、僵直或减速。
4. 原伤害减免后才扣生命；死亡只发布一次，立即取消受害者未完成动作／目标／联动。
5. 每次真实攻击尝试有唯一 action_id／hit_index／target；是否已结算由该动作保存，历史反馈不充当命中账本。

普通敌人与 Boss 使用同一防御结果和伤害应用规则。Boss 外部僵直交给 boss 模块改变它自己的动作状态，不再在 Enemy 或另外的 stun_timer 中镜像。
其僵直状态需记录 source_action_id；联动窗口读取该状态的来源和剩余有效性，而不是单凭“敌人当前看起来僵直”。普通敌人也在自身唯一恢复状态记录同样的来源。
减速用一个 SlowEffect { factor, remaining }；重复应用取更强减速、较晚到期，不叠乘。减速到期、复活和敌人替换清理；其速度约束必须进入物理 motor。

## 4. 普通攻击与技能时间线

以下参数用于首轮验证，均是 Kiva 建议值，不冒称来自原作。
所有命中使用真实三维姿态、Body::aim_position 和当前视线；普攻每个目标在同一次挥击中至多命中一次。

| 动作 | 建议参数 | 时间与效果 |
|---|---|---|
| 锤普攻 | 24 伤害，2.8m，完整周期 0.60s | 0.12s 命中；按面朝的前方区域选敌，不要求锁定 |
| 链斧普攻 | 18 伤害，2.6m，完整周期 0.40s | 0.08s 命中；与锤普攻共用准入／结算方式 |
| 锤 E | 20 伤害，目标距离 <=4.5m，目标周围半径 3m，CD 3.0s | 0.20s 砸地，以目标脚底区域结算；活目标真实向上发射约 3m；动作共 0.50s |
| 鸟铳 Q | 40 伤害，距离 <=22m，僵直 0.45s，CD 4.0s | 妹妹出场，0.18s 一枪，0.40s 收招；不开放联动 |
| 链斧 E | 24 伤害，自身半径 3m，减速到 65% 持续 1.5s，CD 3.0s | 0.15s 环扫命中，0.50s 收招；不要求目标，不开放联动 |
| 链斧弓 Q | 35 伤害，距离 <=12m，僵直 0.90s，CD 4.0s | 妹妹出场，0.15s 射出链斧，0.30s 命中，未接 Tab 时 0.75s 收回完成 |

普通技被接受时开始对应冷却；无效目标／距离／动作状态拒绝时不启动。接受后挥空、目标走开或被障碍挡住，保留已开始的冷却。
技能检查范围与视线至少在起手和实际命中各进行一次；不能因起手时看得见就隔墙命中。
第一版的枪／箭使用固定时间点的命中判定，显示弹道与它对应，不新增有独立伤害时钟的弹道物理。每一发分别检查当前视线和存活。

链斧离手期间哥哥不能普攻或使用 E；Q 冷却不能重置这一事实。Tab 从这次 Q 的后续阶段转入联动，共用原 action lineage；完成／取消时统一恢复手持，不能让链斧既在弓上又在哥哥手上。
对于其他普通技，第一版一个玩家同一时刻只接受一个进攻动作；Q 由妹妹演出，哥哥仍保持近战身份，按普通移动控制移动，不同时接受另一个新攻击。
主动作恢复期结束后才能再起手；锤 E 的恢复不能阻止其有效 Tab 分支。

## 5. 两套联动

### 5.1 锤鸟：击飞 → 妹妹三枪

前置条件：本次锤 E 对原选中敌人确实造成伤害并成功击飞；目标存活且仍在空中。
候选联动窗为击飞命中后 0.85s，与真实落地条件取较早者；仅击飞周围其他敌人不能伪造原目标的窗口。

接受 Tab 时消费窗口并锁定原目标；三个时间点为相对 Tab 的 0.30／0.42／0.54s，每发建议 28 伤害。
0.00–0.20s 镜头进入低位仰视，最后一枪后保持到 0.68s，0.68–0.96s 回到普通镜头。

- 每发有自己的 hit_index，不把三枪合成一笔伤害和三次纯特效。
- Tab 触发后，目标正常落地不取消这次承诺；发射时仍检查原目标存活、可见和射程。无效单发跳过，不追踪到其他敌人。
- 目标死亡／移除、Boss 转阶段时立即停止后续未发射枪，并用最后有效瞄准点进入镜头恢复。
- 最后一发真正成功命中时，建议沿用一次现有 3 固定步 HitStop，前两发不重复请求；普通 Q 不触发专用狙击停顿。
- 哥哥在联动期间锁定主动移动和新动作，但仍参与物理、受重力和敌人攻击，不获得演出无敌。

### 5.2 链斧弓：命中僵直 → 拉近＋三箭

只有本次 Q 对原目标真正造成伤害并施加僵直才建立窗口；截止时间不晚于这次僵直到期。
被免疫、目标已死、链斧被墙挡住或仅有受击动画时不开窗。
接受 Tab 必须原目标仍存活、仍有本次僵直、与哥哥高差建议 <=1.5m，且哥哥接地。

Tab 后最多拉近 0.65s，建议最大平面速度 18m/s，离目标脚底平面距离约 1.4m 时停止主动拉近；
妹妹在相对 Tab 的 0.12／0.28／0.44s 各射一箭，建议每箭 18 伤害，0.65–0.93s 收招与回镜头。

- 拉近以目标当前物理位置计算方向，由 motor 转为有限速度／位移意图，接受斜坡、胶囊和 Avian 碰撞；不直接写 Position／Transform，也不用火炮的抛物线 Leap 冒充拉近。
- 已经接近目标时停止拉动，继续按时间线完成剩余有效箭，不推着目标穿走。
- 连续约 0.12s 未取得有效前进、明显障碍阻挡或超出允许高差则中止，停止额外拉力，清理尚未发射箭并回镜头。
- 每箭从妹妹的模拟射击源重新检查目标与视线；一次可见不保证后三次都命中。
- 目标自然结束原僵直不取消已接受的联动，伤害仍能使其死亡；死亡／无敌／移除则停止。
- 取消与完成都归还链斧，清空离手状态；不重复施加已结算的 Q 命中。

### 5.3 两套共用的失效规则

| 情况 | 联动窗／动作／镜头结果 |
|---|---|
| 未接受 Tab 时超时、原目标落地或原僵直到期 | 清窗口，不能补放 |
| 窗口中手动换组 | 允许空闲换组，清窗口，冷却保留 |
| 动作执行中再次按 Tab／左键／E／Q／1／2 | 拒绝且消费输入，不打断、不排队到结束 |
| 中键解锁或改锁 | 当前锁定显示改变，原窗口与执行目标不被改写 |
| 玩家普通受伤 | 扣血与反馈，第一版不追加所有普攻都打断技能的新硬直规则 |
| 玩家死亡、目标死亡／移除、F2 替换敌人 | 清动作、窗口、妹妹出场和旧命中；切入普通镜头或有界恢复，不残留拉力 |
| 目标转阶段无敌 | 剩余攻击停止；不绕过无敌恢复阶段 |
| Esc／失焦 | 时间线冻结，输入清空，鼠标累计丢弃；恢复后继续已承诺动作，不补播失活期间输入 |
| F3 换外观 | 仅换哥哥显示身体，不重置技能、物理、妹妹或镜头时间线 |

## 6. 固定步与输入契约

~~~mermaid
flowchart LR
    A[原生与 Web 输入] --> B[持有状态与有序边沿]
    B --> C[固定步准备：消费输入与推进动作]
    C --> D[运动目标与 Avian 求解]
    D --> E[发布当前物理快照]
    E --> F[玩家攻击结算]
    F --> G[普通敌人与 Boss 决策和来袭结算]
    G --> H[耐力恢复与瞬移清理]
    H --> I[只读动画、妹妹、HUD、相机]
~~~

现有 HitStop::begin_tick 仍在步头锁定执行决定，所有新增准备／资源系统共用 SimulationActive／HitStop 门控。
准备阶段在 motor 前消费本次输入，推进旧计时，接受动作并生成该步要执行的标记；物理后以更新后的空间状态解析标记和控制效果。
当前系统有玩家先于 Boss 结算的顺序，第一版保持这一优先关系，不新增“敌我同帧交换伤害”规则。

- 一次技能冷却、一次动作 elapsed 每固定步只前进一次；动作新建从 0 开始，不在两个系统重复推进。
- 标记用越界判定 previous < marker <= current，一次步长跨多个标记时按时间顺序处理；不要求浮点时间恰好相等。
- 新输入不直接触发伤害，HUD 就绪也不能越过模拟的动作准入。
- 右键必须使用有序 Pressed／Released／Cancelled 边沿；原生用实际 MouseButtonInput 事件，Web 桥增加边沿队列的一次性消费接口。保持现有 heldKeys 和其他一次性按键的语义。
- 显示帧零固定步时边沿保留，多固定步时只有第一步取走；同帧按下／松开不能折叠为一个 held=false。
- Web 与原生长按时长统一按有效固定步累计；完整发生在两个采样之间且没有有效固定步推进的手势按短按处理，不用墙钟在恢复时补算长按。
- 重复按下、浏览器自动 repeat、捕获点击、非可信事件和其他窗口输入不产生额外攻击。
- clear 立即清设备队列，并锁存防御取消事实到恢复首步；它不重置跳跃额度、闪避进度、已承诺技能或冷却。
- 队列需要有界，例如每批最多 64 条边沿；溢出视为取消当前手势并要求新按下，不能留下永久按住。该限制是工程防护，不是游戏冷却。
- 原生和 WASM 必须共同更新接口及其真实调用方；不保留 JS 右键计时与 Rust 另一份计时。

## 7. 妹妹、武器、镜头和 HUD

### 妹妹出场与临时模型（D01 已确认）

采用临时模型方案：哥哥复用现有选定身体，妹妹先使用明确独立的临时人形与骨骼姿态；锤、鸟铳、链斧和弓用程序化几何做出可辨识轮廓。
该方案验收的是独立出场、射击归属、武器种类与动作完整性，不宣称正式角色美术已经完成。
正式妹妹和四件武器及配套动作后续接入，保留来源、许可和转换记录；不作为第一版开始的前置条件。
临时模型也必须有清晰区别，不把现有长刀／火炮仅改名称就当作新武器通过验收。

逻辑演出接口不与具体美术资产绑定：

- 妹妹平时不占碰撞位，普通 Q 和联动时出现，结束后短暂退场；同一玩家最多一个逻辑妹妹与一个显示根，复用网格和材质。
- 出场点从哥哥脚底、Facing 和侧后方偏移求出；模拟确认射击源不穿墙，必要时缩小偏移。真实发射与视觉枪口使用同一源姿态和方向。
- 出场脚底查询实际支撑面，不固定 y=0；有近邻障碍时不能把妹妹生成在墙另一侧。
- 短技能期间出场位置固定；拉近联动时妹妹留在出场点发箭，哥哥由物理拉近。技能时钟决定她何时可见，客户端插值位置与骨骼。
- 哥哥用近战动作，妹妹用射击／拉弓动作；反馈归属、枪口火花、箭起点和声音来自同一 actor／action_id／hit_index。
- 普通命中与配套专用冲击不能播放两次枪声。替换正式模型仅改变 client，不改变命中、耐力和冷却。

### 相机

普通相机高度、后退比例、FOV、画面下三分点和鼠标灵敏度不变。
锤鸟沿用现有低位背后肩侧仰视设计；链斧弓建议以哥哥胸口附近高度、身后约 2.6m 平视原目标，拉近时随同一显示根移动。
两种镜头均按同一固定步时间线进入／保持／恢复，复用已有球体扫掠净空。
联动期间丢弃鼠标水平样本而不累计，结束恢复原 ViewYaw；死亡、模式替换和取消必须有恢复路径。
普通联动射后回镜头约 0.28s；切模式发生在暂停时可直接清为普通镜头，不能依赖一个暂停后不再前进的恢复时钟。

### HUD 与外观

- 底部显示生命 1000 上限及耐力条，右下显示当前绑定组、E 近战、Q 远程、右键防御和 Tab 联动。
- E／Q 分别显示冷却；Tab 提示绑定具体前置条件，窗口过期立即隐藏；链斧离手时显示近战不可用／回收中。
- 无锁定隐藏顶部目标血条；HUD 目标来自 Combatant 当前锁定，不拿联动原目标强行覆盖它。
- F3 保留哥哥身体外观和服饰，近战武器按当前组展示；避免 appearance::reconcile 再把锤／斧替换成长刀。
- Rust 生成显式枚举／数值快照；JS 不根据中文标签选武器、不独立计时、不改模拟。
- 更新进入／暂停卡片、页面 HUD、原生标题与无障碍说明，移除 Q 切目标、滚轮切人格、火炮跃进、强化／能量等旧或后置提示。
- 美术许可、音效来源和临时资源状态按实际记录；沿用已可用声音可以做适配，但不宣称是这些新武器的原作声音。

## 8. 迁移与回退

按 [实施计划](implement.md) 的检查点逐步替换；优先把一个完整新武器组做通，再删除旧模式、旧狙击／火炮旋斧和落点选择专用状态。
不并行维护两份生命、目标、冷却、妹妹身份或防御计时，也不为旧内部函数建立长期兼容层。
每一阶段更新实际消费者和对应测试；旧行为测试按新验收改写，但保留验证物理、一次消费、暂停和资源复用的有效断言。
现行 .trellis/spec 与 docs/architecture 只在实现落地后更新，旧方案文档加历史／替代指向，不改写旧执行记录。
回退以实际获授权的阶段提交／差异为单位，不清工作区、不触碰用户对源文档的修改；规划阶段不自动提交。
