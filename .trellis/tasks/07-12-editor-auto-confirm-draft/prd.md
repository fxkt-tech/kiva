# Editor 自动确认 Draft 开关

## Goal

在 editor 中增加“自动确认 Draft”开关。开启期间，每个 Draft 环节在内容就绪 1 秒后自动确认并提交，不限于 LLM 生成的 Draft；关闭时不自动提交，Draft 仍保留给用户手动确认。

## Background

- 用户需要控制生成完成后的 Draft 是否自动提交。
- 开关状态必须在请求完成时生效，因此用户可在请求进行期间关闭它，阻止该请求完成后的自动提交。
- Draft panel 可从当前 Draft 类型和 generation record 判断内容是否就绪；自动确认以这一 UI 状态为边界，LLM pending request 仅继续服务浏览器通知。
- 当前手动确认入口是 `confirmDraftAction(gameId)`，它先确认 Draft，再规划下一 Draft，并刷新 editor/preview；自动确认应复用该入口（`src/app/actions.ts`、`src/components/editor/draft-panel.tsx`）。
- Editor 是服务端页面，Draft panel 中已有客户端通知组件；开关和完成后的条件提交可保持为局部客户端能力，无需把偏好写入游戏数据。
- 当前相关 editor 文件存在用户未提交改动，后续实现必须在这些改动之上增量修改。
- 当前确认入口随后会规划下一 Draft；若下一 Draft 也需要 LLM 生成，开启状态将形成连续的“生成 → 确认 → 下一 Draft”流程，直到用户关闭、生成失败、遇到非 LLM Draft 或游戏流程结束。

## Requirements

- editor 提供可明确识别当前状态的自动确认开关。
- 开启时，任何 Draft 类型在内容就绪 1 秒后自动执行现有确认/提交流程。
- 普通 Draft 创建即视为内容就绪；LLM Draft 在本次生成成功或失败并展示最终内容后视为就绪，不能在生成进行中提前确认。
- 初始 LLM 生成不得用遮罩阻塞整个 Draft panel；生成中状态显示在 Generation 操作按钮上，Draft 内容保持可见。
- 关闭时停留在待确认状态，不自动提交。
- 1 秒倒计时期间关闭开关会取消提交；重新开启时，若当前 Draft 已就绪，则重新计时 1 秒。
- 自动确认应复用现有手动确认行为，避免出现两套提交语义。
- 手动与自动确认都必须携带期望的 Draft ID；服务端只确认仍为该 ID 的当前 Draft，防止近同时提交误确认刚规划出的下一 Draft。
- 生成失败、无有效 Draft 或提交失败时不得伪装为已确认，并沿用现有错误反馈机制。
- 自动确认以当前展示的 Draft ID 和就绪状态为准，不依赖 LLM pending request；页面打开已有 Draft 时，开启状态会在 1 秒后确认它。
- 开关作为浏览器级用户偏好保存在 `localStorage`，跨 editor 刷新和不同游戏保持一致，不写入游戏记录。
- 首次使用且尚无已保存偏好时，开关默认关闭；只有用户明确开启后才启用自动确认。
- 开关保持开启时，后续所有 Draft 环节均在就绪 1 秒后自动确认，不在每次确认后自动复位。

## Acceptance Criteria

- [ ] 开启开关后，普通 Draft 到达 1 秒后自动提交。
- [ ] LLM Draft 生成进行中不提交，生成结束并展示最终内容 1 秒后自动提交。
- [ ] 初始 LLM 生成期间没有“Generating LLM draft...”全屏遮罩，Generation 按钮显示禁用的旋转状态。
- [ ] 关闭开关后任何 Draft 都不自动提交，用户仍可手动确认。
- [ ] 1 秒倒计时期间关闭开关会取消提交；重新开启后从 1 秒重新计时。
- [ ] 自动确认与手动确认走同一提交入口，并避免重复提交。
- [ ] 生成或提交失败时保留可理解、可恢复的 UI 状态。
- [ ] 刷新或首次打开已有就绪 Draft 时，开关开启则在 1 秒后自动提交。
- [ ] 切换开关后刷新 editor 或打开另一个游戏，开关状态保持一致。
- [ ] 首次使用且无已保存偏好时，开关呈关闭状态。
- [ ] 开关保持开启时，自动确认后规划出的下一 Draft 无论是否需要 LLM，都继续按相同规则自动确认。
- [ ] LLM 生成失败后以页面展示的回退 Draft 进入 1 秒倒计时；游戏流程结束且无 Draft 时不提交。

## Out of Scope

- 改变 Draft 的生成内容或提示词。
- 自动重试生成或提交。
- 改造 editor 之外的 Draft 流程。
