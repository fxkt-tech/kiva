# 实施计划

本文件已随整体方案获用户明确实施批准；各子任务按显式依赖进入in_progress。研究脚本能读资源仍不能单独证明产品实现。

## 顺序和依赖

1. 完成父任务源身份、肌肉转换、音效及运行时研究；收敛逐状态映射与真实限制。
2. 评审父任务 PRD/design/本计划及四个子任务。通过评审后只 start 实际交付子任务，父任务保留总体验收职责。
3. 子任务动作：先H0：横刀第1段+真实Avatar的全身/30指/root与可信原生逐帧对照（不能以非零运动通过），H0通过后再三段、防御、通用和远程；完成准备包/运行时数据/来源清单与离线verify。
4. 子任务音效可与动作并行：只读原PCK，按HIRC恢复事件并有界提取，转小范围同源Ogg；保留变体/延迟和真实映射，完成verify。
5. 子任务三段规则可与资产并行：先锁公开快照类型和pure numeric profile，再连段缓冲/取消/防御gesture/真实运动cue，使用实际FixedUpdate回归。
6. 前三项输出可用后，启动表现子任务；先通用双来源采样/binding，再角色/手指和阶段动画，最后音效与共享查看页目录，禁止另造查看页姿态。
7. trellis-check独立审核全部改动并自行修复其负责范围的问题；主会话运行集成与浏览器检查、记录局限，落地契约后再更新canonical specs。
8. 用户本轮已明确授权提交/推送；核对已通过检查与当前代码后提交本批交付，再归档本次五个已验收任务、记录日志并推送main。

## 必须执行的检查

    python3 scripts/prepare-naraka-animations.py --verify
    python3 scripts/import-naraka-audio.py --verify assets/prepared/naraka/audio
    make check
    cargo clippy --locked --target wasm32-unknown-unknown -- -D warnings

上述脚本已由子任务固定并实际通过，完整记录见各delivery；普通verify不依赖游戏目录。构建使用临时dist，Trunk参数 --locked true --offline true --public-url ./，本机缓存的wasm-bindgen0.2.130显式加PATH。不要启动常驻开发服务或操作用户服务。

## 集成验收场景

- 真游戏单击仅1段，连续按键1→2→3；早按/晚按/狂点、第三段尾帧、换组/技能/暂停/死亡/F2重置；各段一次命中，空挥无impact。
- 右键短按、长按、无敌人释放、真正拆招/格挡/弹反成功；动作正确且成功音效不提前、不重复。
- 实际接受两次跳跃/拒绝第三次、接触落地、短闪/疾跑、堵墙无脚步、传送/复活无脚步；HitStop/失锁恢复无补声。
- 李火旺/愁铃客玩家/白灵淼与四武器，左右掌、五指、手腕与握柄近景；Boss仍保持燕云原动作。
- 查看页各阶段暂停/拖轴/往返切来源、三角色/四武器、复制trace、root/子路径；手持/掌框来自相同生产代码。
- Chromium使用已有隔离Xvfb helper，headless已知不能用普通截图判断GPU输出。测试fixture结束后只清理本次进程。

## 风险与停止条件

- Humanoid是首要技术风险。只找到名字、generic附件或肌肉数组均不足以启用新动作；转骨后的身体、指轨、根/feet处理须有真实证据。不得静默回退成旧动画然后标为永劫完成。
- 未定位的某个可选通用片段可明确沿用现有对应动作并列为缺口；三段横击、振刀与振刀成功核心片段不可用时不能通过整个需求验收。
- 音效缺少专用映射时只可明确使用原共享武器事件，不把横刀反击挥刀当振刀碰撞成功声，不把序号接近当语义。
- 不动原native rest/IBM、移动物理与现有BGM；性能/体积新增要报告，不能承诺未经测量的节省。
