# HUD与镜头比例调整

## 目标与确认
用户要求先提交推送上一轮修复，再按docs/TODO.md的修改HUD需求先出方案、紧接实现，继续遵守架构和规范。本轮HUD实现不自动提交。
参考docs/hud_lol_game.png：保留现有深青、暖金、薄边框风格；不做左侧训练竖栏，其余大致布局及镜头/人物屏幕比例接近参考。

## 范围
- 紧凑底部操作栏：七属性在左、角色标记、四技能居中，生命/能量条位于技能区下方，六装备格在右；技能/装备/被动/护盾/状态与现有交互保留。
- 小地图固定右下角、贴近底边；选中目标在左上，时间/基地状态和常用操作收紧到顶部，减少大标题遮挡。
- 默认镜头拉近，使英雄屏幕尺寸约为当前两倍、接近参考的8–12%画面高度；继续自由镜头、滚轮、Y/Space、边缘/方向键平移。
- 保留骨骼模型、武器、真实拾取和标签锚点；通过镜头调整屏幕比例，不修改碰撞/攻击/移动等模拟数值。
- 响应式至少覆盖1920×1080、1280×800、800×600、1000×720 DPR2及窗口缩放；七属性/四技能/六装备/小地图无重叠或溢出。
- 血条仍使用原逐帧位置通道，资源/属性/冷却来自实际只读快照；不在JS重建战斗逻辑或计时。

## 验收
- [x] 参考布局形成：紧凑下沿操作栏、右下角地图、左上目标、顶部紧凑信息，无左侧竖栏，风格延续。
- [x] 默认人物大小明显增大并有实际截图/屏幕比例依据；相机操作和首次开局/重开/普通恢复语义保持。
- [x] 四技能、六装备、七属性、资源/护盾/被动/状态与键鼠操作均可用，HUD点击不穿透世界。
- [x] 所列视口和DPR2可读且无交叠、裁切、横向溢出，地图不再被抬到主画面中。
- [x] 实际投影拾取/血条跟随/暂停/选角/重开及相应质量检查通过，规范与TODO更新。

## 范围外
左侧训练工具栏、经验/经济/召唤师技能/新玩法、改英雄技能或属性、替换骨骼美术、服务接管及本轮HUD自动提交。

用户要求小地图固定展示整张地图，矩形框标示屏幕范围，支持点击和拖动来移动主镜头。追加设计见[minimap.md](minimap.md)。

- [x] 完整地图边界、静态基地/中路和当前可见单位始终按同一坐标转换绘制；小地图不跟主镜头裁切。
- [x] 矩形视野框由实际地面四角外接范围生成，随镜头、滚轮和窗口变化逐帧更新，不使用固定尺寸或JS预测相机。
- [x] 捕获鼠标后可左键点击地图定位、拖动视野框保持抓取偏移；镜头统一经过Rust相机门控、边界夹紧，并切换到自由镜头。
- [x] 松开、暂停、失焦、失锁、重选均清理拖动/旧意图；UI操作不产生走位、攻击或施法，DPR2与小窗口可用。
- [x] 原生/Node专项及真实浏览器点击、拖动、边界、缩放、恢复验收通过，规范同步。
