# 攻击判定统一：动画烘焙的扫掠命中与真实弹体

状态：规划中。用户于 2026-11-12 提出；提交与推送未授权。

## Goal

用户发现刀挥到的位置和实际造成伤害的位置不一致。希望整个攻击判定用一种最可靠的方式统一实现，以后改连招时只填数据，不再关心判定这个基础问题，专注玩法。

## 现状依据（已核实）

- **近战判定与刀无关。** 玩家普攻 `resolve.rs::strike_arc` 在 `hit_time` 时刻按脚底距离 ≤ `range`、正前方点积 > `MELEE_ARC`(0.25) 结算一次。Boss `boss.rs` 在 `ACTIVE`(0.22s) 窗口内第一帧满足 3D 距离 ≤ 3.2、高差 ≤ 0.9、半角 70° 且无遮挡就结算。普通敌人在蓄力 0.42s 结束时瞬时结算。
- **动画时间不统一。** 玩家普攻按 `elapsed/duration` 线性铺满整段片段，三段共用同一个 `hit_time`，每段片段的实际接触帧却不同。Boss 用分段比例：预警对应 0–45%，攻击窗口对应 45–65%，伤害在 45% 处结算。技能（锤 E、链斧 E）和普通敌人的姿态由渲染端自己的 `clock` 驱动，从首次看到事件的那一帧才开始计时。
- **姿态有历史依赖。** 切片段有 0.08s 混合，切骨架淡出约 0.135s；CC0 层另有 0.055s 过渡。
- **刀刃位置可以离线计算。** 武器挂点为 `stickman::attachment_transform`；武器模型从握点沿 +Y 延伸（锤尖约 0.81m，链斧约 0.76m；Boss 长刀长度需从网格计算）。`PreviewRig::seek` 能以 1/60s 回放真实的 `RigPose::frame`，测试构建可以通过 `bundle` 读取随包资源。
- **远程全部瞬时命中。** 在标记时刻做射线视线检查后直接扣血。链斧投掷有离手和命中两个时刻，画面上线性飞行。

## 已定决策

| ID | 决策 |
|---|---|
| D1 | 判定形状与轨迹从动画离线烘焙，生成模拟层数据；不手写 |
| D2 | 覆盖全部攻击：近战、技能、普通敌人、Boss、远程 |
| D3 | 远程改为有飞行时间的真实弹体 |
| D4 | 每种角色固定一个标准外观烘焙；换外观不影响玩法 |
| D5 | 弹体支持按技能配置是否锁定：锁定则追踪原目标（可被遮挡），不锁定则直线飞行；当前远程技能全部锁定 |

## Requirements

| ID | 需求 |
|---|---|
| R1 | 所有近战命中由攻击者刀刃在该 tick 扫过的体积与目标受击体相交决定；命中点是接触点 |
| R2 | 判定数据来自离线烘焙，存在模拟层；动画或武器变化后由测试提示重新烘焙 |
| R3 | 动画按模拟层的动作时间采样，画面中刀的位置与判定在容差内一致 |
| R4 | 远程攻击是有飞行时间的弹体，按 tick 扫掠命中，可被遮挡 |
| R5 | 防御顺序（闪避、拆招、弹反、格挡、受伤）、能量、耐久、事件归属沿用现有 `apply_hit` / `settle_defense` |
| R6 | 新增或修改招式时只改数据并重新烘焙，不写判定代码 |
| R7 | 提供调试显示，叠加扫掠体积、受击体和弹体 |

## 子任务

1. `11-12-anim-sim-clock`：攻击动画统一由模拟时钟驱动（前提）
2. `11-12-melee-sweep`：离线烘焙与近战扫掠判定，含调试显示和过期校验（依赖 1）
3. `11-12-projectiles`：远程真实弹体（可与 2 并行，依赖 1 中的时间统一）

## 不在范围

- Boss 和普通敌人的远程攻击、新招式、数值平衡。
- 按外观分别烘焙（D4）。
- 布料、发丝和武器附件的物理。
