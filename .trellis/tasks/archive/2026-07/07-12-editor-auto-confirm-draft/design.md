# Editor 自动确认 Draft 开关 — Technical Design

## Summary

在 Draft panel 上增加浏览器级自动确认控制。当前 Draft 内容就绪且开关开启时启动 1 秒计时，计时结束后调用现有 `confirmDraftAction(gameId, draftId)`。自动确认与 LLM pending request 解耦，覆盖所有 Draft 类型。

## Component Boundary

- `DraftPanel` 继续负责服务端渲染 Draft 与 generation 快照。
- `llm-generation-notification.tsx` 保留 LLM pending request 与浏览器通知职责，并承载同一区域的自动确认控制：
  - 读取和写入 `localStorage` 中的自动确认偏好；
  - 渲染 Draft header 中的 toggle button；
  - 根据 Draft ID、就绪状态和偏好管理 1 秒计时并调用 `confirmDraftAction`；
  - 保留现有浏览器通知行为。
- `confirmDraftAction` 保持唯一确认入口，继续执行 confirm、continue 和 editor/preview revalidation，但扩展为接收期望的 Draft ID。

不新建服务端配置字段，也不把自动确认偏好传入 game record。

## Storage Contract

- 使用稳定、带命名空间的单一 `localStorage` key，例如 `kiva:auto-confirm-draft`。
- 缺失或无法识别的值视为 `false`；首次使用默认关闭。
- 值为浏览器级全局偏好，不按 game 区分。
- 同标签页点击 toggle 后必须立即更新 React 状态和存储；完成 effect 读取最新状态，避免闭包捕获请求开始时的旧值。
- 跨标签页 `storage` 同步不是该功能正确性的必要条件；每个标签页以自身当前展示的 toggle 状态控制当前 Draft。

## Auto-confirm Data Flow

1. `DraftPanel` 为普通 Draft 传入 `ready=true`；初始 LLM Draft 在 generation record 出现前传入 `ready=false`，成功或失败 record 出现后传入 `ready=true`。
2. 自动确认 control 在 `enabled && ready` 时为当前 `draftId` 启动 1000ms timer。
3. 开关关闭、Draft ID/就绪状态变化或组件卸载时清理 timer。
4. timer 到期后在 transition 中调用 `confirmDraftAction(gameId, draftId)`。
5. action 成功后 revalidation 展示下一 Draft；开关保持开启时，新 Draft 重复同一流程。
6. LLM pending request matcher 仅继续负责浏览器通知，不参与自动确认决策。

## Concurrency and Failure Safety

- timer 在依赖变化和卸载时清理；同一组件状态只保留一个当前 timer，确认后 Draft ID 变化会建立下一环节的新 timer。
- 自动确认和手动确认都把当前 Draft ID 传给同一服务端入口；`gameActions.confirmDraft` 在 game lock 内核对当前 Draft ID，仅匹配时确认。近同时提交中的后到请求因 ID 已变化而成为 no-op，不能误确认下一 Draft。
- 自动确认 action 失败时 Draft 仍存在，用户可以查看并手动重试；本任务不增加自动重试。
- 页面初次打开或刷新已有就绪 Draft 时，若持久化开关开启，会按产品要求重新计时 1 秒后确认。
- 用户在请求期间关闭或开启时，完成处理读取最新偏好，实现双方确认的对称语义。

## UI

- toggle 放在 Draft panel header，与当前 generation 状态和通知按钮同组。
- `AutoGenerateDraft` 只保留隐藏表单和自动提交 effect，不渲染 panel 遮罩。
- LLM Draft 始终渲染 Generation 操作区；初始生成时按钮以 disabled spinner 表示 pending，生成完成后恢复为 Regenerate，Draft 摘要与操作区保持可见。
- 使用明确的开启/关闭图标状态，并提供随状态变化的 `aria-label` 与 `title`，例如 “Enable auto-confirm draft” / “Disable auto-confirm draft”。
- 按钮应使用现有 icon button 样式；开启态需要可视觉辨识，不仅依赖 tooltip。
- hydrate 前按安全默认值关闭展示，挂载后读取 `localStorage`，避免服务端访问浏览器 API。

## Compatibility and Rollback

- 未设置偏好的用户行为完全不变：默认关闭，继续手动确认。
- 删除 toggle、偏好读取和 Draft timer 中的 action 调用即可回滚；game 数据格式无需迁移。
- 实现时保留当前工作区对通知、prompt mode 和 preview v2 的未提交修改。

## Test Strategy

- 将偏好解析和“某完成结果是否应自动确认”的决策提取为纯函数，用 Vitest 覆盖：默认关闭、有效开关值、失败不确认、无匹配 pending 不确认、成功且开启确认。
- 扩展 server action 测试，覆盖 expected Draft ID 匹配时确认、不匹配时不确认，以及近同时重复确认不会推进两个 Draft。
- 扩展 Draft panel 静态渲染测试，确认 toggle 的可访问标签存在。
- 保留并扩展现有 completion matcher 测试，覆盖初始加载不误判。
- 运行相关测试、全量 typecheck；必要时运行全量 test 以验证服务端确认与 editor 流程未回归。
