# Core motion implementation boundary

The behavior gap is that the client treats all defense phases as one boolean and all source poses as Yanyun indices, while new authoritative melee stages and native Naraka poses need distinct identities. The client alone owns sampling, retargeting, animation transitions and inspection; simulation continues to own input acceptance, motion and hits.

Owned changes: source_animation.rs adds a versioned decoder and independent rig selection; animation.rs/preview.rs consume stage/defense snapshots and expose the same controller to inspection; avatar.rs/hand.rs cache per-source semantic bindings without modifying native rest/IBMs; companion.rs invokes actual ranged source poses before explicit grip IK; viewer only displays the shared result and source metadata. Audio, controls, web.rs, offline assets and simulation remain other workers' ownership.

Keep the existing CC0 and Yanyun APIs compatible. Naraka is enabled only after the real verified binary exists. Different source hierarchies never share local-pose blend arrays. Cross-rig transitions fade through the common CC0 layer; exact native Yanyun palettes remain only for the same native rig. Tests cover old behavior, malformed source data, real source/target hand geometry and shared preview/game inputs. Native output and browser acceptance are coordinated by the parent.

## Implemented client contract

- The default resource contains the verified 44-clip, 63-node `naraka/l22_male_skeleton` KIVASR02 asset alongside the unchanged 986-node Yanyun KIVASR01 library. Each source pose identifies its rig. Decoder timestamps are f32 seconds; exact keys return verbatim, and adjacent positive f32 intervals are divided without an EPSILON floor. Different rigs fade through the common CC0 layer and never share local-pose arrays or palette indices.
- Each target caches independent driver, native palm and three-joint finger calibrations per source. Native Naraka distal direction comes from actual preceding child offsets (-X), while glTF target frames retain their own geometry. Finger rotations blend locally before own-length FK; original IBM/rest, wrist/MCP frames and the signed +0.055m physical grip remain intact. Original Chou/Yanyun still uses its exact native palette.
- Ordinary attacks read committed `ActionSnapshot.melee_stage`, elapsed and duration. Hit markers, old melee feedback and success feedback cannot restart them. Defense reads the complete immutable snapshot. Effective Parry remains simulation-owned at .18s; the display-only .60s riposte retains its missed-frame tail. A preempted gesture ID stays preempted, including a new Hit/HeavyHit whose complete .24/.30s reaction fits inside a .32s render frame. A new gesture ID can play normally.
- `SourceScope` declares full body, upper body/fingers with CC0 lower body, or fingers with CC0 body. Production crouched melee/defense keeps the existing .12s crouch transition and actual lower-body pose. Actual moving Deflect/Guard uses shock upper body over actual CC0 gait; movement may preempt an expired-window Parry tail. The same avatar composition is used by game and viewer, with no viewer offsets.
- Raw sniper/FK layers and only `male_bow_attack_01` use declared upper-body composition because their native extracted Hips is near/below zero. `male_bow_hold_idle_01` remains full body. Raw mode keeps original native matrices and has no weapon IK. Finger-only clips compose over the reference CC0 body. Scope, actual supplementary finger layers, stage, phase, gesture age, interruption and explicit fallback are visible in the trace.
- The sister uses verified shared female-FK overrides (`male_fk_hold_idle_01`, `male_fk_attack_01`) or the verified shared bow clips, retargeted through the canonical donor onto her own proportions. Native upper body/fingers precedes the established physical two-hand grip correction and CC0 lower-body choreography. Other FK phases remain available in raw source inspection.
- Native airborne sampling removes the extra Hips Y while preserving leg rotations; raw comparison retains original body elevation. Native `applyRootMotion=false` leaves MotionRoot stationary, so clearing only that root would double the physics jump.
