# Bug Analysis: 短击飞窗口与浏览器自动化往返

## 1. Root Cause Category

- Category: E — 隐含假设。
- 原测试假设读取屏幕坐标、移动鼠标、读取选择结果再按Esc能在800ms击飞内完成。
  软件WebGPU和CDP往返会继续消耗模拟步；运动中的坐标也可能在下一次点击前过时。
- 证据：先观察到Airborne与正确高度，失败时已落地；后续选择实际成功，但暂停快照已经没有状态。
  16项客户端测试中的真实击飞/可见GlobalTransform拾取/暂停场景通过，未据此修改游戏规则。

## 2. Why Fixes Failed

1. 等水平强制运动结束再采样身体坐标：减少水平偏差，但剩余空中窗口不足以容纳全部往返。
2. 删除选择结果的主机等待：仍把多个鼠标往返放在短窗口中，暂停可能落后于结束。
3. 在浏览器观察到选中后立即走真实捕获丢失暂停：消除Esc往返，但鼠标移动本身仍可能晚于动画。

## 3. Prevention Mechanisms

| Priority | Mechanism | Action | Status |
|---|---|---|---|
| P0 | 测试时序 | 在弹丸飞行阶段提前移动光标到演示配置规定的击退终点上方；实际点击仍等待状态和运动结束事实 | DONE |
| P0 | 平台事件 | 观察到目标在空中被选中时调用原生exitPointerLock，走生产捕获丢失暂停路径，移除主机额外往返 | DONE |
| P0 | 证据保留 | 暂停快照必须仍含Airborne、正高度和正确selected；之后验证tick/状态/高度/坐标冻结 | DONE |
| P1 | 诊断 | 失败输出展开JSON含selected、abilities、完整坐标，不再被Node折叠成Array/Object | DONE |
| P1 | 规则隔离 | 用公开命令的ECS测试验证精确时钟与拾取；浏览器验证真实投影/事件，不增加修改World后门 | DONE |

## 4. Systematic Expansion

相似风险存在于短前摇、极快后摇和高速弹丸。先分辨主机延迟、显示帧、模拟步与80ms快照，
不要延长生产控制时间、提高轮询次数或放宽断言来掩盖自动化时序。
测试预定位依赖演示R距离4的内容契约，数值改变时和最终位移断言一起更新；
浏览器实际选择/空中暂停断言与可见Transform的ECS拾取回归共同覆盖显示和点击框错位。

独立复核另捕获两个真实数值边界：秒制f32无法扣除一步，以及极小速度无可表示位移。
前者在注册统一拒绝，后者在移动所有者释放运动锁，均添加公开行为回归。
