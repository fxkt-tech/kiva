## 2. 建议接口：三层分离，但不增加通用技能脚本

建议保留 `Targeting` 与 `UnitCommand::CastAbility` 的调用方式，定义内部拆为：

```text
AbilityDefinition
  targeting + range + windup/recovery/cost/cooldown
  execution:
    Impact { delivery, nonempty ordered effects }
    Dash { self motion parameters }
    Channel { duration, interval, pulse: Impact }

delivery: DirectUnit / DirectionProjectile / HomingProjectile / Area
effect: Damage / ApplyStatus / Displace
```

这里的枚举名是建议，不是既有类型。Dash 是施法者的执行行为，不是伪装成“命中自己的伤害投递”。
Projectile/Area 的模拟实体只保存不变的效果快照与投递几何；伤害仍通过 damage.rs 唯一实现。
引导保存同一份提交快照，每个脉冲创建一次命中载体；控制中断只停止后续脉冲，已提交载体继续。

注册必须拒绝空效果、非法参数、无目标的 DirectUnit、Direction 与 HomingUnit 等不兼容组合。
不要用三个彼此无关的 Option 字段暴露一堆运行时不合法状态，也不必为一个本地实现引入 trait 注册。
effects.rs 可拥有内部 `PendingImpacts` 和小型解析函数；调用方提交意图，测试通过相同公开构造/施法入口。

### “原子”需要限定含义

保留“提交之前整份定义/快照验证成功，才扣费和启动冷却”的原子性。
命中后的有序效果建议采用逐项语义，不承诺回滚已扣血：

- `[Damage(致死), Stun]`：死亡清理后跳过眩晕，不能给尸体留下状态。
- `[Stun, Damage(致死)]`：先产生状态应用，再死亡并清理状态，最终无存留控制。
- 位移被墙截断不应撤销本次已成功的伤害或眩晕。

因此不要把“一个命中包原子处理”写成“所有效果必须全成功，否则回滚整次命中”。

## 3. 控制权限与中断建议

以下均是需要整体评审的 Kiva 初始项目规则，不是对某商业游戏的兼容声明。

| 来源 | 自主走路 | 普攻 | 非移动技能 | 自身冲刺 | 已开始动作 |
|---|---|---|---|---|---|
| Slow | 允许，按最终移速 | 允许 | 允许 | 不改独立冲刺速度 | 不额外打断 |
| Root | 禁止 | 范围内允许 | 允许 | 建议禁止启动并中断当前自身冲刺 | 只打断自主移动，保留非移动前摇/引导 |
| Stun | 禁止 | 禁止 | 禁止 | 建议禁止并中断 | 中断普攻前摇/后摇、施法前摇和引导；已提交间隔/消耗保留 |
| Airborne | 禁止 | 禁止 | 禁止 | 建议禁止并中断 | 同硬控制；浮空时仍可被命中，战斗距离仍用平面 |
| 强制位移运行中 | 禁止自主移动 | 建议禁止 | 建议禁止 | 禁止新启动 | 自身 Motion 锁不等同于 Stun 状态 |

Root 是否打断已经提交的自身冲刺是产品规则，源码不能决定；本项目可采纳“普通冲刺会停，外来强制位移不受其影响”的统一初版。
不需要本期再发明“不可阻挡”技能标志来穷尽所有特例；后续有具体技能需求再加明确规则。

权限应由活动状态和 Motion 锁聚合，不能写成可被某个状态结束直接改回 true 的布尔量。
例如 Stun 结束但 Root 未结束时，只恢复攻击/普通施法；强制位移结束但 Airborne 未结束时，依然不能行动。
动作的取消通过 actions.rs 所有的统一中断函数，位置/路线通过 movement.rs 的对应操作处理，避免多个模块直接改相同运行态。

### 持续意图与 Stop

建议保存被控制前的 UnitOrder，解除后重新验证目标并重规划路径；不自动重放被中断的 CastAbility。
已提交的普攻间隔、技能冷却和能量回复继续走时钟，不因控制而冻结或刷新。

建议 Stop 始终可清理持续意图与普通路线，但不能结束强制位移或撤销已提交冲刺/弹丸。
当前 `Movement::default()` 会把 dash 一起抹掉，必须替换成有明确范围的清理操作。

“受控时是否接受新的移动/攻击/施法意图”需要产品评审：拒绝并反馈、或缓存新目的等结束后执行，是不同 UX。
若初版选择拒绝，Move/AttackMove 需要移动权限，Root 下仍可发 AttackTarget；旧 AttackMove 可保留意图并执行允许的普攻部分。
若选择缓存，也必须仅缓存持续指令，不让被拒绝的技能偷偷在解除控制后自动释放。

## 4. 固定步与一 tick 控制的反例

如果控制在 tick t 的动作/移动后命中，设置 `expires=t+1` 并在下一 tick 指令前移除，
N=1 的状态会在限制任何后续动作前消失。必须明确“持续 N tick”拦截哪些完整动作步。

与根代理确认的建议阶段：

1. 推进 tick / 重生 / 外部属性请求。
2. 使用当前活动状态和 Motion 锁门控命令、动作提交、持续指令和移动。
3. 移动后推进并移除旧状态，立即更新对应权限与属性来源。
4. 统一解析当前步的命中效果包，按列表应用新状态；本步新状态不再递减。
5. 完成死亡与所有权清理后发布可观察状态；本步不再运行动作/移动循环。

tick t 末段命中、remaining=N 的状态限制 t+1 到 t+N，t+N 的移动之后移除，t+N+1 可行动。
因此 Direct/Channel 也只能在动作阶段提交效果包，不能提前直接眩晕仍待遍历的 actor。
所有单位同一步已完成提交的攻击/技能仍有效，保持当前“提交先于伤害/死亡”的规则。

强制位移在下一次 movement 步开始，其最后一段移动后释放自身 Motion 锁即可，因为本步已没有动作循环。
不要在同一步的旧控制到期后再补跑一次动作循环，否则会打破 N tick 定义并允许额外提交。

控制时长建议使用有界整数 tick 或毫秒构造器。直接 `ceil(f64::from(0.1_f32)*60)` 会得到7而非期望6；
100ms=6 tick 与最短1 tick 都应成为验收场景，避免重复攻速的浮点边界问题。

### 命中顺序必须显式稳定

当前 projectile/area 只把伤害压入队列，查询遍历顺序不构成未来多控制的优先级契约。
建议给已收集命中包定义稳定排序键：tick、约定的投递阶段、来源实体/提交序号、载体、目标，
包内严格使用 effect_index 顺序；同 tick 两个强制位移“后者替换前者”才有明确含义。
这不承诺跨平台浮点确定性，只是不把结果委托给偶然的 ECS 遍历顺序。

## 5. 状态来源、叠加与属性模块

建议每次应用有唯一实例 ID，实例保留来源事实、目标生命引用、强度、剩余 tick 与叠加键。
来源死亡/移除不自动撤销已命中的普通控制；其身份用于归因，不是效果继续存在的依赖。

### 叠加建议与反例

- 硬控制：同源刷新可以选 `max(old_remaining, new_duration)`；不同来源独立，权限是并集，时长不做加法。
- Slow：建议独立实例并取当前最强强度。强减速先到期后，较弱但仍有效的减速必须接替。
- 不要把70%持续0.2秒与20%持续10秒的同源减速，合并成70%持续10秒；这会同时借用最强强度和最长寿命。
- Airborne 的重施加还涉及显示轨迹；若简单刷新同一实例并把进度置0，会在空中跳回地面。
  可保留独立短期击飞实例并取连续高度曲线的最大值，或单独设计高度续接；不能只处理控制到期而忽略视觉连续性。

### 最强 Slow 应只提供一份属性贡献

30%和50% Slow 若每个实例都向当前 additive_percent 提交负数，会得到80%而非50%。
状态模块应按目标聚合最强 Slow，只维护一份私有属性来源；结束或死亡时移除该贡献，
别让每个状态实例各自按相反数“恢复”最终移速。

这里有两种真实的产品选择，不能混写：

- 保留既有加算层：向 additive_percent.move_speed 写 `-max_fraction`，20%加速与30%减速为
  `base*(1+0.2-0.3)=0.9*base`。实现最小，但“30%减速”不会从减速前速度实际扣除30%。
- 建议供用户评审的规则：新增最终移速减速层，先算既有 `(base+flat)*(1+sum(percent))`，
  再乘 `1-max_slow_fraction`；20%加速与30%减速为 `base*1.2*0.7=0.84*base`。
  这是属性运算契约的实质扩展，尚非用户确认或既有规范；其余六项属性维持原算法。

后者可在 AttributeModifier 增加专用于移速的有限 `[0,1]` 系数，默认1；状态的唯一贡献写入
`1-max_fraction`。多个独立属性来源的该系数做乘积，但多个 Slow 状态仍先取最强，因此不能
把每个 Slow 分别写成属性来源。限制该层只做减速能避免乘数溢出的额外语义，也不为其它属性
预建尚无需求的乘法框架；名称和文档需明确这是最终移速系数而非通用属性倍率。

当前 AttributeModifier 在 attributes.rs:129 派生 Default；增加倍率后必须手动保持默认1，
否则原来使用 `..Default::default()` 的所有属性来源会意外把移速乘成0。
所有有限输入仍以 f64 聚合，乘该系数后才进行最终 f32 饱和，不能先截断大值再减速。
系数 `[0,1]` 连乘不会上溢；极小结果下溢为0可以沿用允许零移速的规则，删除来源仍从完整
原始集合重算，不依赖除法恢复。不得根据当前最终移速反推一个负 flat 来假装乘法，这会产生
循环依赖，并在其它来源变化时保留错误的减速量。

需要单独验收：默认来源保持全部旧行为；20%加速叠30% Slow 得0.84倍；减速前超过 f32 上限、
减速后回到范围内时不应提前截断；最强 Slow 移除后立即退回次强值；非法系数原子拒绝。

命中末段的 Slow 不能仅入公开 AttributeChanges 队列等下一 tick，否则状态和最终属性投影会短暂不一致。
建议把 attributes.rs:225 的提交实现提取为模拟内部、同步且校验的操作，由原公开队列与状态解析在既定阶段调用。
这仍由属性模块唯一写缓存，不给客户端暴露直接写最终值的接口。
同一步旧 Slow 到期、新 Slow 命中时同步重算两次是可接受的；不要为了少算一次延迟所有效果写入，
否则未来“改抗性→伤害”的列表顺序会失效。

## 6. 生命身份与强制移动

当前重生复用同一 Entity，状态清理本身不能阻止已存储的旧施法目标在新生命上重新生效。
例如短重生在 `respawn_units` 阶段完成，旧 homing projectile 在稍后的 advance_projectiles 只看到 alive=true，
或长前摇的锁定技能在目标死而复生后重新验证通过。

建议给单位增加私有 LifeEpoch，在复活时增加；存储的 UnitTarget/状态/Motion 引用 `(Entity, LifeEpoch)`。
指向技能在接受意图时固定目标生命引用，提交与命中再复核；地面范围技能仍可合法击中范围内的新生命。
来源引用保留原生命用于归因，不要求来源仍存活。死亡清理状态与位移，复活不继承旧控制或旧高度。

Motion 建议区分“已提交自身 Dash”和“外来强制位移”，都由 movement.rs 唯一写平面位置。
每步 sweep，不能走穿墙、不能同时再叠加普通步行预算；撞墙的结束及自身操作锁释放必须显式。
新强制位移替换旧位移时，只移除旧 Motion 所有的锁，不能清除仍存在的 Root/Stun/Airborne。
被位移后保留持续意图，但清理旧路径并按新位置重规划。
完全贴墙导致零位移时，是立即不建立 Motion 还是保留最短一 tick 动作锁，需要与“碰墙结束”规则保持一致。

## 7. 击飞的显示、拾取与血条

战斗继续使用 Vec2 平面，击飞不应通过提高渲染高度改变伤害距离或让地图障碍失效。
但显示身体、可点击 AABB、逐帧血条和诊断 screen 必须使用同一可见姿态。

当前最易漏掉的是 controls.rs:88–94：它用未插值的 UnitPose 计算 AABB，改 UnitVisual 高度并不会自动修正拾取。
建议把点击迁移到最后一帧已显示的 UnitVisual GlobalTransform 与 Pickable，使用与当前相机射线一致的可见位置；
至少不得继续将被击飞的身体点击框留在地面。输入只输出 Entity 意图，最终是否合法仍由模拟判断。

一个较小的展示方案是让 UnitVisual 根承载“平面插值+击飞高度”，底座用反向局部高度留在地面；
已有血条锚点随 GlobalTransform 自动抬高，UnitModel 子层仍只负责后摇姿态。
若选择仅抬高 UnitModel，则还必须为 Pickable、label anchor 和完整快照 screen 接入同一高度视图，
不能出现三个各自计算高度/进度的实现。

AOE/落点/攻击范围指示仍以地面位置绘制，死亡/重生应重置前后显示位置和击飞高度，避免从空中插值飞回出生点。
暂停应保留已经显示的高度/姿态，而非重设插值进度；已有后摇暂停回归可作为同类约定的依据。

## 8. 建议实施切片与验收

1. **先结构迁移**：按现有 Q/W/E/R 的效果逐个转入新执行/投递/载荷结构，先通过已有65项规则/适配测试。
2. **第一条完整路径**：敌方单位 Direct+Stun；接通权限、中断、时长、反馈和只读显示。
3. **第二条完整路径**：Point Area+Damage+Slow；验证顺序、来源、最强减速与属性同步，覆盖多效果。
4. **Root 与现有移动/引导**：验证能普攻/非移动施法、阻止走路/自身Dash、已有持续意图恢复与Stop清理。
5. **Motion 与 Airborne**：复用扫掠，验证强制移动锁、碰墙/覆盖、视觉高度/点击/血条/暂停、生命代次。
6. **演示及集成**：选择有意配置的演示装配，再同步按键/鼠标按钮说明和浏览器断言；不通过具体技能ID分支实现规则。

必测反例：

- 最短1 tick控制确实阻止恰好一个后续动作/移动步，100ms在60Hz下阻止6步。
- 同一步双方已提交的技能都保留，控制不能因actor查询顺序提前阻止对方同一步提交。
- 致死伤害后的状态不存留；先状态后致死也经过完整清理。
- 强 Slow 到期后弱 Slow恢复；同源弱长状态不延长原强短状态的强度。
- Root结束但Stun仍在、Stun结束但Root仍在、Motion结束但Airborne仍在，分别恢复正确权限。
- 被控制前已经出手的普攻继续命中，取消前摇不扣资源，打断引导不退费且只取消后续脉冲。
- Stop在控制/强制位移期间清理持续意图，不取消外来位移；解除后不自动重放一次性技能。
- 旧锁定目标死亡并以同一Entity重生，旧施法/跟踪载体/位移引用不能作用于新生命。
- 被击飞单位的身体可点、血条正确抬升、DPR2及窗口缩放不造成点选错位。
