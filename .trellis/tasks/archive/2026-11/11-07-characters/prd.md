# 角色定义与开局选择

状态：实现与验收完成，包含用户补充的重新选择角色及整场试炼重开。基线`7eb69c0`；实施范围为本文和design.md，实际证据见[verification.md](verification.md)。
开发服务仍由用户管理，本轮未请求提交或推送。

## 目标与价值

完成`docs/TODO.md:4`的角色系统：玩家开局选择一个角色，按角色初始属性和技能开始试炼。
将角色默认配置、本局实际装配、运行状态分别管理，支持不同角色复用同一技能，
为之后随机赋予技能和装备能力扩展提供稳定的创建入口。

用户在接受“先角色系统，再装备系统”的建议后要求“先出方案”。
前序已确认的方向是定义与实例分离、默认与本局装配分离、开局选择并由实际数据驱动HUD；
本方案的两个演示角色及具体数值属于建议内容，供本次一起审阅。

## 需求与采用规则

| 编号 | 需求 | 可观察结果 |
|---|---|---|
| R1 | 定义角色及独立实例 | 注册角色名称、初始属性和默认技能；同角色多个实例的生命/冷却/状态独立 |
| R2 | 默认与实际装配分离 | 创建时可使用默认或完整显式四槽；空槽明确为空，目录不被改写 |
| R3 | 选择与预览 | 开始前查看角色初始属性、技能及目标方式，开局后HUD与所选角色一致 |
| R4 | 身份及装配贯穿生命周期 | 暂停/恢复与死亡/重生保留角色身份和本局实际装配 |
| R5 | 开局提交明确可靠 | 未确认开始前无玩家且模拟冻结；捕获成功及合法选择才创建唯一玩家，失败可重试 |
| R6 | 选择与游戏输入隔离 | 选角操作不移动/攻击/施法，不在开局后重放；通过暂停菜单结束旧局并重新选角 |
| R7 | 可用的Web体验 | 两角色选择、错误提示、键盘访问、小窗口/DPR2布局；原紧凑HUD保持 |
| R8 | 架构与兼容性 | NPC/原创建接口/既有战斗规则保留；新增角色靠配置，未来显式技能装配可复用 |

本期采用以下行为：

- 首次进入显示选角，默认预选旅者；只有点击开始且鼠标捕获成功后才创建玩家。
- 选角期间地图/NPC可以显示，游戏时钟、巡游和战斗均冻结，不预生成隐藏英雄。
- 选角预览显示由核心规则计算的初始值，不能用JS另算或伪造战斗实例。
- 显式装配替换完整四槽，None为空槽；沿用重复技能ID合法、冷却按槽独立的现有规则。
- 捕获失败、过期选择或出生失败不创建半个角色，保留选择并提示；快速点击不能启动旧预览角色。
- 开局后Esc/失焦只暂停，恢复继续同一个玩家；角色死亡不回选角，重生不重新装配。
- Web是选角主入口；Native保留编译和默认旅者运行路径，不另做native选角界面。

## 演示内容建议

提供旅者、秘术师两角色，复用已有技能和模型；具体数字见[设计文档](design.md#3-内容装配)。
旅者保持当前属性和点选Q/方向R；秘术师使用不同初始属性、方向Q/自身引导R，
用于证明角色和技能是可组合的数据关系，无需增加技能效果或按角色分支的战斗代码。

## 用户补充：重新选择角色（已确认）

用户指出还缺少重新选择角色，并明确选择“重开整场试炼”。这覆盖首版不提供重开入口的限制，
属于当前角色功能的继续实现，不需要重新询问实现许可；不提交/推送、不接管开发服务的约束继续有效。

- R9：暂停菜单提供“重新选择角色”；结束旧局后返回Selecting，保留上次角色预选，用户可重新选择并开始。
- R10：整场重开，清除旧玩家/NPC/已提交弹丸/范围/引导、待执行命令/属性变更/命中包/反馈，
  训练NPC回到初始生命和位置，模拟tick=0、镜头复位。地图和定义目录继续复用。
- R11：成功返回后丢弃同批未消费的选择/启动/返回意图；后续批次的旧版本启动及旧玩家返回亦拒绝。
  普通暂停继续仍保留原玩家，只有明确重新选角才重开。SelectCharacter是当前Selecting界面的同步意图，不新增跨局异步传输。
