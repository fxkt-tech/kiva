# 游戏模式时长控制与剧本模式

## Goal

以游戏 `ae9b3a8a-fb8b-43cf-901b-252ad49b0341` 为首个诊断样本，完成两个相互独立但共享底层规则和发言预算的运行模式：

- **游戏模式**保留当前自由推演，玩家根据各自可见信息自主发言、行动和投票，同时把导演版标准成片从当前 76 分钟级控制到 28–32 分钟，验收长局不超过 35 分钟。
- **剧本模式**在角色与规则身份确定后，先生成并验证一份主题化、可执行的单局剧本，经导演审核批准后再按剧本演出；所有最终台词逐场限长生成。

两种模式都不得通过视频倍速、音频截断或事后删除推理来满足时长。

## Background

### 用户决定

- New Game 必须明确提供“游戏模式”和“剧本模式”，而不是给同一玩法增加一个轻量剧情开关。
- 游戏模式沿用当前规则、Draft 推进和玩家自主决策，只修改发言长度、上下文预算与时长观测。
- 剧本模式是按批准剧本表演的节目形态：剧本可以预定玩家立场、身份声明、夜间行动、投票、放逐、反转与胜负；规则引擎只负责保证这些计划真实可执行。
- 为避免术语混淆，库中跨局复用的《未明档案》称为**主题模板**（当前 `GameScriptDefinition/Snapshot`）；绑定一局角色、隐藏身份、事件走向和时长的产物称为**单局剧本**。
- 单局剧本预先生成完整分场、所有结构性选择和每场预算，但不预先生成全部最终台词。最终台词在执行到对应发言 Draft 时生成。
- 剧本生成并模拟验证后进入导演 Review；只有手动批准才锁定并开始产生正式事件。
- 批准后结构只读，执行阶段只允许在分场与长度合同内调整台词；第一版不支持中途重规划剩余剧情。

### 样本局量化证据

- 当前 Preview 与导出都使用导演视角，会收入狼队私聊和夜间行动（`src/app/games/[gameId]/preview/page.tsx:39-45`、`src/server/video-export/snapshot-builder.ts:28-39`）。按当前代码、玩家语音和闻舟预制语音重新编排后，共 105 个场景、`4,562,453ms`，即 **76.04 分钟**；纯公开视角仍为 **64.76 分钟**。
- 导演版中 35 段白天发言占 `54.38` 分钟，15 段狼队意见占 `9.48` 分钟，6 段遗言占 `8.23` 分钟；加上首夜战术后，LLM 发言场景约占整片 `94.8%`。主理人、阶段、行动和结算不是主要膨胀源。
- 白天发言共 `19,192` 个非空白字符，平均 `548` 字 / `90.6` 秒，中位数 `513` 字，最长 `992` 字 / `155.3` 秒；遗言平均 `473` 字 / `79.4` 秒；狼队意见平均 `211` 字 / `35.3` 秒。
- 周序 8 段发言合计约 `12.59` 分钟，夏弥约 `10.04` 分钟；迟木同为 8 段但约 `4.23` 分钟。人物风格正在决定节目时长。
- 第一天单次平均 `308` 字，第二天升至 `511` 字。平均 Prompt 长度从第一天 `4,398` 字符增至第二天 `10,809`、第三天 `18,343`、第四天 `23,741`，后期模型不断收到并复述旧发言、历史票型和前置立场。

### 已确认根因

- `PromptTaskSpec` 没有目标字数、硬上限或节目时长合同（`src/core/llm-task-specs.ts:45-65`）；发言解析只校验 `text` 非空。OpenAI-compatible 请求也没有请求级输出上限（`src/core/llm.ts:117-124`）。
- 白天任务要求回应已有主张，但没有落实上一提示词设计中的“不得复述整条时间线”（`src/core/llm-task-specs.ts:128-154`）。
- 长局上下文目前只是每个知识区最多 40 条、每条最多 800 字（`src/core/prompt-builders.ts:27-28,321-340`），没有按当前轮、关键结算、未解决冲突和玩家最新立场选择。
- 主题在每次请求中注入同一段名称、背景和氛围词，只要求“偶尔使用意象或类比”（`src/core/prompt-builders.ts:220-226`）。57 段发言中 40 段使用主题词，但主要是“档案”35 次、“封存”16 次、“红印”11 次、“存根”10 次；“冷雨”“旧纸”“停电”各 1 次，“凌晨”0 次，说明主题只形成了词汇皮肤。
- 当前主题数据只有 `name/theme/background/atmosphere/presentation`（`kivdb/scripts.json:3-20`）；没有世界观身份映射、单局分场、角色命运或结局回收合同。

### 现有架构约束

- `advance-planner.ts` 已按事件前缀逐个生成 Draft，`rules.ts/state.ts` 负责合法目标、结算与胜负。剧本模式应驱动同一个推进器做 dry-run 和真实执行，不能复制第二套狼人杀状态机。
- `Game.script` 已是不可变主题快照；Preview 和 Export 使用同一快照。单局剧本也必须按相同原则保存，不得通过 ID 回读可变库数据。
- 私密行动依赖事件 visibility 和 `projectVisibleEvents`，不能靠 Prompt 文本过滤保密。
- 本任务是 `07-12-character-host-video-redesign` 的子任务，并与 `07-11-redesign-prompt-structure` 的任务规格、信息边界和一次 repair 合同相邻。

## Requirements

### R1. 双运行模式与生命周期

- `Game` 快照保存 `game | scripted` 运行模式；旧游戏缺少字段时只在内存中按 `game` 读取。
- Game mode 不生成或依赖单局剧本，现有事件路径、行动选择、投票与胜负不变。
- Scripted mode 在正式事件开始前经历 `generating → review → approved/running`；生成失败、校验失败或待审核时不得 Advance、Confirm、配音或导出。
- New Game 中运行模式、主题模板、Preset/随机座位是三个独立决策。

### R2. 统一的生成时长合同

- 建立单一 `speech-budget` 所有者，为每种 speech Draft 定义目标字符区间、硬上限、最低有效内容和预计语音时长。
- 人物风格只能在预算内改变句式、节奏和重点，不能扩大上限。
- Prompt 明确要求只保留当前任务所需的结论、关键依据和验证点，禁止复述完整时间线/票型、重复前置观点和 TTS 会朗读的括号舞台动作。
- 本地对完整 JSON 中的 `text` 做统一字符上限校验。首次超长使用现有唯一 repair 机会进行语义压缩；仍超长则保持 Draft 不变并记录失败。
- 禁止字符串截断、未闭合 JSON、音频裁切和视频层删改；不使用角色级 `maxTokens` 粗暴截断推理模型。
- 人工编辑的发言在保存和确认前复用同一硬上限。

### R3. 游戏模式时长与上下文

- 发言上下文按当前日、上一日结构化结算、每名玩家最新立场、未解决身份/查验冲突和本人有效私有记录选择，不再重复注入可供逐字复述的完整历史。
- 票型使用结构化摘要；压缩选择不得改变底层 visibility 或泄漏 host-only/他人私有事件。
- 生成前根据已承诺播放时长和 pacing envelope 选择正常/压缩/临界预算档位；不能为时长改变行动、投票、规则或胜负。
- Editor/Preview 显示已承诺导演版时长与预计区间。理论上的任意超长对局只能明确告警，不能静默裁切。

### R4. 主题模板叙事语法

- 主题模板扩展共同 premise、stakes、角色身份别名、行动别名、公开 briefing、语气规则、禁止捷径和双方结局 frame。
- 《未明档案》把狼人杀规则映射为同一世界中的语义，例如“狼人｜篡改者”“预言家查验｜鉴真”“放逐｜永久封存”，但不改变底层角色、候选、技能和胜负。
- 主题模板不定义角色专属秘密、临时职业或固定玩家命运；这些只存在于绑定具体隐藏身份的单局剧本。

### R5. 结构化单局剧本

- Scripted mode 在角色和隐藏身份确定后生成一份版本化、绑定 Game 输入 hash 的结构化单局剧本。
- 单局剧本至少包含标题、logline、计划胜方/天数/时长、幕与分场、全部行动和投票、身份声明/伪装、每名玩家的发言立场/依据/冲突对象、遗言、反转、结局和每场 SpeechBudget。
- Script Author 可以为了节目剧情计划非最优策略，但不得计划规则非法行为；Scripted mode 是演出合同，不冒充自主竞技模拟。
- 首版由 Author 自动选择胜方；导演可在 Review 整份 Regenerate，不新增指定胜方选项。
- 最终台词不写入预生成单局剧本；执行到当前 speech Draft 时才根据分场生成，因此局部重写不改变结构。

### R6. Dry-run、验证与批准

- 单局剧本生成不能一次依赖巨大自由文本；先生成大纲，再按夜间、白天、PK/遗言批次产生结构化计划。
- 编写器在内存中循环调用现有 `planNextDraft`，通过共享 `applyDraftPayloadEdit`、合法候选、确认、事件追加、派生状态和规则结算完成整局模拟。
- 模拟必须真实到达 `game_ended`，且所有 actor/target/resource/vote/death/winner 与计划一致；最大事件数、昼夜数、repair 次数和预计 35 分钟是失败保护。
- 编译结果中的每个计划步骤与一个预期 Draft 结构签名对应；不得依赖随机 Draft/Event ID 或时间戳。
- Review 展示剧情、角色命运、行动/票型、预计时长和规则/信息边界报告。批准要求 `events.length === 0`、Game input hash 未变化且所有检查通过。
- 批准前允许整份 Regenerate；批准后保存深拷贝不可变快照。

### R7. 锁定执行与 Actor Projection

- Scripted mode 使用批准步骤驱动同一个现有推进器；行动与投票采用计划值并在运行时再次校验合法性。
- 执行游标由 active event index 派生，不保存可能漂移的第二游标。Rollback 可从同一计划重放，不改结构。
- 当前 Draft 与计划中的 type/phase/actor/day/round/voteType 不一致时进入 `script_diverged` 并停止，不自动跳步、选替代目标或切回游戏模式。
- 完整单局剧本仅导演可见。玩家 Prompt 只得到当前 Actor Projection：共同世界观、当前分场、计划立场/披露、本人的可见依据和发言预算。
- 预生成依据保存稳定 step reference；运行时只能映射到已经确认且该玩家可见的真实事件。未来命运、计划胜方和他人隐藏身份不得进入玩家 Prompt。
- 批准后 Editor 的行动、投票、披露计划和结局只读；只允许在当前 SpeechBeat 和硬上限内重新生成/人工调整台词。
- 第一版不支持中途重新规划剩余单局剧本。

### R8. 剧情呈现与声音

- Scripted mode 的幕、分场和结局必须围绕计划并最终实际发生的狼人杀事件形成因果链，不能靠反复主题词证明主题存在。
- 计划可插入不改变游戏状态的动态剧情节拍，由闻舟播报章节、关键冲突和终局回收；Player Context 将其视为节目包装而不是身份证据。
- 动态旁白使用事件级不可变主理人语音并计入批准前预算；Preview 和 Export 消费确认事件与批准快照，不读取候选剧本。
- Game mode 保持当前主题背景/主理人包装，不强制生成单局剧情或插入动态章节事件。

### R9. 持久化作业、兼容与观测

- 单局剧本编写采用可恢复的持久化 job，记录排队、生成大纲、规划、验证、完成/失败进度，避免一个不可恢复的长 Server Action。
- Job 和单局剧本记录 Author 模型、Prompt/编译版本、token usage、attempt 和可操作错误；过期 job 不能覆盖新 candidate。
- Home、Editor、Review、Preview 清楚显示运行模式、剧本状态、预计/实际时长和失败原因。
- 已批准单局剧本、主题、人物、Presenter 和语音资产都使用创建/确认时快照，修改库定义不改变旧局。
- 不覆盖样本局及其用户已有 record/MP3；验收通过临时复制、只读重放和新建剧本局完成。

## Acceptance Criteria

- [ ] 样本局诊断可复现 105 个导演场景和约 76.04 分钟总时长，并给出各事件类型占比。
- [ ] 所有 speech Draft 都有共享的目标区间、硬上限和最低有效内容；超长只触发一次压缩 repair，失败不会确认截断文本。
- [ ] 游戏模式全局样本重放保留关键推理且预计导演版落入 28–32 分钟；代表性验收长局不超过 35 分钟。
- [ ] 游戏模式的行动、投票、角色规则、胜负和 visibility 与当前行为一致。
- [ ] New Game 明确提供两种模式，并与主题模板、Preset/随机座位独立组合；旧游戏显示并运行于游戏模式。
- [ ] 《未明档案》主题模板包含完整叙事语法且不会增加游戏证据或改变合法候选。
- [ ] 剧本模式在事件为空时生成绑定本局 cast/roles/rules/theme 的完整分场与结构选择，并通过现有规则引擎 dry-run 到终局。
- [ ] 至少覆盖好人胜、狼人胜、平安夜、女巫资源、守卫连续限制、PK 和猎人链的有效/无效计划测试。
- [ ] Review 展示故事、角色命运、预计轮数/时长、票型/行动和校验报告；未批准时无法推进、配音或导出。
- [ ] 批准后的真实事件 trace 与计划结构一致；篡改 actor、target、day、round、input hash 或计划顺序会明确偏航并停止。
- [ ] Actor Projection 的所有结构化依据都来自已确认且当前玩家可见的事件；负向测试覆盖未来步骤、狼队密票和他人私有身份。
- [ ] 相同批准剧本重新生成某句台词时可以改变措辞，但行动、票型、披露计划、死亡和结局不变。
- [ ] 剧本模式的结构性 Editor 字段只读，台词编辑复用同一硬上限；Rollback 只能沿原计划重放。
- [ ] 动态章节与终局回收由确认事件驱动，使用不可变闻舟语音，计入 Preview/Export 的统一 audio timeline。
- [ ] 一局真实《未明档案》剧本模式成片具有可复述的主题因果链，不机械复读主题词，导演版落入 28–32 分钟且不超过 35 分钟。
- [ ] 相关单元、repository、server、UI、visibility、playback、voice 和 export 测试，以及 `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm video:smoke`、`git diff --check` 全部通过。

## Out of Scope

- 改变狼人杀角色数量、技能、合法候选、结算或胜负规则。
- 在游戏模式中操纵玩家选择以强行制造剧情。
- 剧本批准后从中途状态重新规划剩余结构。
- 第一版逐字段人工编辑单局剧本；Review 只提供整份 Regenerate 和 Approve。
- 在 New Game 增加指定胜方、指定存活者或固定某个角色命运的高级选项。
- 预先生成并锁死整局最终台词。
- 为旧游戏批量生成单局剧本、替换原发言或覆盖原语音。
