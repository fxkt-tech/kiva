# Boss 播放自己的原作攻击片段

## Goal

愁铃客目前的三招借用 Naraka 玩家横刀普攻（`male_hengdao_attack_light_01..03`），刀刃判定也按这三段烘焙。
改为每个攻击动作播放 `yanyun.bin` 中已具名导入的愁铃客原作技能片段，判定按各片段重新烘焙。

## 资料边界

- `~/go/src/github.com/fxkt-tech/mysrc/boss_01`（仓库外，原在 `mysrc/boss_01`）是同一资源包的中性命名重提取：五棵核心行为树与 `boss.rs` 已用的数据一致，
  动画二进制与旧 `mysrc/choulingke` 逐字节相同。新增可用的只有尚未接入的行为树（受击、虚弱、P1 特殊、分身、死亡）。
- 技能槽 `9002xxxx` → 片段的映射仍未恢复（`skill_slots.json` 全部 `slot_to_animation: null`）。
  **下表的动作 → 片段配对和片段裁剪区间是 Kiva 适配**，不是原作配置。
- 其余 20 个攻击片段的共享骨名未解开，不绑定。

## Requirements

| ID | 需求 |
|---|---|
| R1 | `TrackId::Boss` 以源动作号区分：每个会出招的动作一条时间轴，时长由模拟层的表拥有 |
| R2 | 客户端攻击片段表把每个动作映射到一个原作片段及起点，以 1 倍速播放 `[起点, 起点+时长]` |
| R3 | `make bake-hits` 为每个 Boss 动作从待机烘焙刀刃路径；预警、出招、收招阶段继续全部来自烘焙窗口 |
| R4 | 权重、距离池、冷却、开场招（P1 45、P2 21）、三招一轮、伤害保持不变；每招对目标仍只命中一次 |
| R5 | 删除 Boss 的固定 `STRIKE_DURATION`、按段数（`MeleeStage`）选招的逻辑和借用的 Naraka 行 |
| R6 | 接敌停步距离取刀刃实际扫过正前方目标的最远距离（`HitTrack::frontal_reach`），不再用最大 `reach` |

## 验证记录（2026-11-13）

- `make check` 通过：Rust 340 个（1 个忽略，即烘焙入口）、Node 108 个；WASM Clippy、`git diff --check` 通过。
- `make bake-hits` 连续两次输出逐字节相同。
- 实时测试先失败：Boss 预警中走近目标、收步那一帧，刀尖离烘焙路径 0.31–0.37m。原因是 CC0 状态从走切到停会重启源姿态的交叉淡入，挥刀片段落后自身一帧。改为只在换片段或倒回时淡入后，玩家与 Boss 实时测试均通过；玩家普攻窗口与距离不变，样本只在链式过渡处移动约 1cm。
- 起初按最大 `reach` 停步时，14、24、50 三招从任何距离都挥空（刀只在侧面摸到最大距离，正前方只到 1.0–1.3m）。改为 `frontal_reach` 后，各招从 1.5–4.5m 起手全部命中，大部分到 8m 仍命中；19 和 11 从 5.5m/8m 外起手仍会挥空（近距离池招式）。
- 依赖旧 0.72s 预警和单次挥刀的 5 个防御/闪避测试改为先在同一固定场景里预演一次求接触时刻，再相对它安排防御；弹反-收招测试改用短招 19。

## 未做

- 预警停留以首帧静止姿态表示，未另做蓄力动作。
