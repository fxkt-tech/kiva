# 首次进入加载进度与就绪门槛

用户反馈首次加载后点击“点击进入”常不生效，并明确希望按钮上显示加载进度，加载完成后才允许点击。用户已确认问题主要发生在首次进入，非 Esc 后恢复。

## 需求

- L01：首次打开即显示入口按钮的加载状态与进度，准备完成前真实 disabled，不能从按钮或画布绕过。
- L02：下载阶段以真实字节和已知总量显示进度；总量未知、编译／解码／场景／渲染准备不能伪造百分比，显示可理解的准备阶段。
- L03：仅在必要场景和首次渲染准备真正就绪后才显示“点击进入”；不能只以下载完成或 Startup 系统装配完成为准。
- L04：点击后鼠标捕获进行中有即时反馈，成功后进入；失败可重试，不无限锁住按钮。保持可信用户手势与 pointerlockchange＋焦点确认的既有契约。
- L05：暂停后重新进入不重新下载或显示首次加载进度；保留 Esc／失焦、输入清理、早期DOM状态重放与错误恢复。
- L06：下载或初始化失败显示明确失败与重试；真正 ready 仍可覆盖过早或迟到错误。无新增战斗规则、相机／模型／音频资源变化或常驻服务操作。

## 验收

- [x] 可运行的实际代码反馈循环覆盖当前缺口，记录首次加载／ready／捕获的顺序和可复现信号。
- [x] 冷加载／缓存、已知与未知总量、早期DOM、错误／迟到通知、加载中点击与捕获重试均有真实桥回归。
- [x] 原生／WASM兼容，模拟仍由原输入边界控制，ready不依赖任意等待时长或假进度。
- [x] 浏览器冷加载首击就能进入，加载期间按钮不可点击且有进度／阶段反馈；恢复不重走加载。
- [x] make check、WASM Clippy、临时Trunk构建通过，Cargo.lock与游戏资源未变，浏览器验证独立记录。

实际浏览器完整冷加载／重复加载／无总量／失败和捕获恢复通过；真实HTTP缓存另用相同loader和原生最小WASM验证。不据本机时序宣称复现用户设备唯一根因；证据见 research/integration-verification.md。
