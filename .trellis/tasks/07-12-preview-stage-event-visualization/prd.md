# Preview 舞台事件结果可视化

## Goal

让 Preview 的中央视觉舞台在关键行动与结算环节展示结构化结果，使观众无需只依赖播报和字幕，也能立即理解“谁对谁做了什么、结果如何”。同一舞台表现必须同时适用于浏览器预览和 Remotion 视频导出。

## Background

- 当前中央舞台只保留空白布局槽位，玩家座位、Header、字幕正常渲染，但关键事件没有舞台视觉反馈。
- 首批需要覆盖：守卫守人、狼人刀人、预言家查验、女巫用药、放逐结算、PK 结算、对局结算。
- 现有 `PlaybackItem` 已包含事件生成后的 `title`、`text`、`details`、玩家快照和公开/导演视角过滤结果；设计必须继续遵守既有可见性边界。

## Requirements

- 在每个关键事件所属的播放环节渲染对应的舞台结果，而不是增加独立于时间线的 UI 状态。
- 夜间采用“逐行动展示 + 最终结算”：守护、刀人、查验、用药分别只展示当下行动；夜间结算只展示最终死亡/平安夜，不重放完整因果链。
- 舞台表现需要明确区分行动者、目标、动作与结果，并能表达无人出局、平票、未使用技能等空结果。
- 视觉采用统一“行动者—动作—目标”舞台事件卡；放逐、PK、夜间和对局结算在同一舞台容器内使用专用结果变体，而不是各自建立无关布局。
- 放逐与 PK 结算只展示结论、候选人的汇总票数和弃票数；完整逐票流向保留在事件详情，不进入视频舞台。
- 对局结算只展示胜利阵营与获胜原因，不展示全员身份阵容；Preview 是上帝视角，左右玩家卡已经持续显示身份。
- 动画统一为“容器淡入上移 → 行动连线展开 → 结果印章强调”，不得使用随机、闪烁或依赖真实时间的效果。
- 私密夜间信息不得泄漏到 public audience；仅 director audience 可展示已经允许其看到的私密行动和查验结果。
- HTML Preview 与 Remotion 导出复用同一确定性视图模型，不依赖浏览器时间、随机数或额外请求。
- 视觉设计应与现有昼夜调色板、左右座位卡、Galgame 字幕带和 Header 共存，不遮挡字幕或关键座位信息。
- 本任务先完成方案与验收范围，未经用户批准不开始实现。

## Acceptance Criteria

- [x] 首批七类行动/结算均有明确的场景映射、信息层级和空结果表现。
- [x] 方案明确 public/director 两种 audience 下每类信息是否可见。
- [x] 方案定义从 `GameEvent` 到 `PlaybackItem`、舞台视图模型、HTML/Remotion 渲染的单向数据流。
- [x] 方案定义静态布局、入场/强调/退场节奏以及多目标或冲突结果的表现。
- [x] 方案包含测试策略，覆盖事件映射、隐私边界、确定性与预览/导出一致性。
- [x] 用户审阅并批准最终 `prd.md`、`design.md` 与 `implement.md` 后才进入实现。
