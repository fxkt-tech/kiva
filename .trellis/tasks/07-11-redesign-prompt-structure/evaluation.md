### 公开狼人发言专项回放

当前 Draft 的 v1 输出曾直接写出“狼队刀 1 号”，把 3 号声称的查验当成确定身份，并多次制造数值概率。最终 v2 回放结果：

- 没有出现真实刀口、首刀/团队策略、狼人队友或密票信息。
- 3 号的预言家身份与查验结果始终表述为“3 号声称”，没有升级为确认事实。
- 引用 1 号“暂时没发现矛盾点”时明确保留 1 号归属，没有转挂到 3 号发言下。
- 该复杂样本曾使用一次语义修复后成功；后续验证发现这种基于措辞的本地拦截误报严重，因此只作为 Prompt 质量样本，不再作为运行时校验依据。

## 回放推动的二次修正

第一次 v2 回放仍发现三类语义问题，因此没有直接把“结构合法”当作完成：

1. 狼队战术仍可能给对称候选制造“更像神职/平民”的差异。Task Spec 现明确主备只是中立排序，并禁止从角色总数为具体候选制造概率差异。
2. 狼队意见可能把“没有被提及”“没有反证”包装成证据。Task Spec 现要求无新增证据时只以团队共识解释沿用目标。
3. 女巫解药摘要对刀口事实的描述曾被误判。当前规则下狼刀目标必然不是狼人，因此 Prompt 允许描述好人阵营损失，只禁止继续推断具体平民/神职身份。
4. 狼人密票会继承旧队内讨论中的伪证据。阵营讨论在 Prompt 中明确标为“提案与未证实判断”，密票摘要被引导只记录跟随共识或偏离原因。
5. 公开狼人可能直接或间接泄露刀口/首刀策略，也可能把他人的查验主张当事实、把一句原话归错座位。这些继续作为回放评分维度和 Prompt 改进依据。

真实重放证明 Prompt 仍可能生成数值概率、虚构发言风格和“神职候选”，但关键词/正则无法可靠理解开放式自然语言和具体规则。最终实现只对 JSON、字段、枚举、合法候选和机制约束执行本地校验；语义质量通过回放评估继续优化，不触发失败或修复。

## 覆盖边界

当前游戏记录没有可重放的遗言、PK 发言、猎人开枪、放逐投票和 PK 投票等后续局面，因此真实模型对照只覆盖上述五类。全部 12 种 LLM Draft（以及 `vote_cast` 的 exile / PK 两个语义分支）已经由任务矩阵、Prompt 结构、候选合法性、可见性和生成修复测试覆盖。

结论：五类真实样例达到设计文档建议的上线门槛，但在积累后续局面的真实输出前，应继续保留 `KIVA_LLM_PROMPT_VERSION=v1` 回滚开关。
