# 重设计狼人杀提示词结构

## Goal

重新设计狼人杀全部 LLM 请求的提示词结构，使模型能够先正确理解当前场景、听众、信息边界和本轮任务，再以人物风格完成有局势价值的发言或合法行动；重点改善场景错乱、私密信息泄漏、无依据推理、机械复述、角色风格压过任务，以及行动目标不稳定等问题。

## Background

### 当前调用全集

代码中只有两个 LLM 调用入口，但共覆盖 12 种 Draft：

- 发言类 5 种：`wolf_strategy_given`、`wolf_opinion_given`、`day_speech_given`、`last_words_given`、`pk_speech_given`。
- 行动类 7 种：`guard_protect_selected`、`wolf_vote_cast`、`seer_check_selected`、`witch_antidote_decided`、`witch_poison_decided`、`hunter_shot_decided`、`vote_cast`。
- 主持人播报、阶段推进、夜间结算、查验结果、狼队结票、放逐结算和游戏结束等事件不请求 LLM，不属于本任务的 Prompt 类型。

### 日志与代码证据

`docs/examples/` 中的五份日志和当前 12 人游戏的生成记录暴露了以下问题：

- 首夜 `wolf_opinion_given` 把狼队私聊误判为“第一天白天”，以平民视角说话、询问昨夜是否有人死亡，并刻意不向狼队友暴露身份。当前 Prompt 没有明确频道、听众、允许披露的信息以及尚未发生的步骤。
- `wolf_strategy_given` 在没有任何玩家行为证据时编造具体座位的神职倾向和错误概率；人物的“概率分析”偏好被模型误解为必须制造数字结论。
- 后续狼人意见机械复述队长的完整战术，有的提前假定目标已经死亡，有的在首夜对尚未发言的玩家编造“沉默”线索。
- 多次 `wolf_vote_cast` 生成失败并留下 `Illegal targetPlayerId`；当前候选目标仅以松散文本列出，`json_object` 也没有提供字段级结构约束或修复请求。
- 首夜 `seer_check_selected` 在信息完全对称时稳定选择列表首项 `p1`，理由只是“确定其身份”；Prompt 没有说明对称局面、历史查验、信息价值或中立打破平局方法。
- `witch_antidote_decided` 把被袭击玩家直接称为“好人”，混淆“被狼刀”与“已知阵营”；Prompt 没有把确认事实、推断和他人主张分层。
- 女巫用药理由只是规则复述，没有显式呈现药品库存、当夜是否已经用另一瓶药、首夜自救和资源权衡。
- 首日第一位 `day_speech_given` 只复述“平安夜”后过麦；人物的“少说话”特征压过了本轮至少应贡献一个观察框架或暂定策略的任务要求。
- 预言家公开报出 1 号是好人后，又在同一段发言中讨论 1 号可能是狼人；模型没有被要求维护“已确认私有事实”和本轮公开立场的一致性。
- 狼人在公开发言中直接使用“狼队刀 1 号”等私密视角；当前“只能使用可见信息”只限制模型能知道什么，没有说明哪些私有信息可以用于决策、哪些不能对当前听众说。
- `reasoning` 经常变成人设符合度自评、措辞解释和“没有暴露队友”的元叙事，而不是简短、可审计的决策依据。
- 两类通用模板都注入完整规则、角色和原始时间线；真正的当前任务位于长消息末尾，相关信息、无关信息、确定事实、玩家主张和私密讨论混在同一时间线中。

代码检查还发现 Prompt 契约与规则契约存在漂移风险：

- `vote_cast` 无论 `voteType` 都使用“所有存活且非自己”的候选目标，PK 投票没有限制为平票候选人。
- Prompt 总是允许弃票，解析也接受 `null`，没有服从 `allowAbstainVote`。
- `voteReveal=after_all_votes` 时，已确认的单票事件仍为 `public`，后续投票者的 LLM 上下文可能提前看到他人投票。
- `roleActionPromptSnapshot` 被加入所有行动，包括语义不同的白天/PK 投票，容易出现“白天投票时要求夜晚使用技能”的冲突。
- 预言家合法目标没有排除历史已查验目标；即使 Prompt 建议不重复查验，规则候选和校验仍可能允许它。

## Requirements

### R1. 穷举式任务建模

- 12 种 LLM Draft 必须各自映射到一个明确的任务规格；新增 LLM Draft 时，TypeScript 应强制补齐任务规格。
- 任务规格至少定义：场景、时间点、频道/听众、目标、最低有效贡献、禁止行为、相关规则、相关上下文、候选项和输出契约。
- 不再通过 `draft=...`、`phase=...` 等内部枚举要求模型自行推断游戏语义。

### R2. 固定的信息优先级

每个 Prompt 必须按以下语义优先级组织：

1. 当前场景与听众；
2. 本轮唯一任务和完成标准；
3. 已确认事实、私有事实、未证实主张和团队讨论；
4. 合法候选与当前资源；
5. 仅与本轮相关的规则；
6. 角色目标与人物表达偏好；
7. 输出协议。

人物风格只能影响证据权重、表达方式和风险偏好，不能覆盖本轮任务、事实一致性、规则或信息边界。示例口头禅是风格参考，不得机械重复。

### R3. 知识与披露分离

- `projectVisibleEvents` 继续作为玩家能知道什么的基础边界。
- Prompt 上下文必须进一步区分：公开确认事实、玩家公开主张、自己的私有事实、阵营私聊、受保护秘密和未知信息。
- 每个任务必须明确当前听众以及披露规则。模型能看到私有信息不等于可以在公开发言中直接说出该信息。
- 狼队公开发言不得泄露狼队友、狼队私聊或密票；狼队私聊可以直接讨论狼人身份和战术。
- 神职可在公开发言中策略性地选择隐藏或公开自己的身份/结果，但输出必须与选择一致。

### R4. 最小相关上下文

- 身份牌和阶段开始等能由“当前场景”表达的事件不再重复塞入时间线。
- 事件按语义分区，而不是作为一条无差别原始时间线：公开事实、公开发言/主张、公开票型、个人私有记录、狼队讨论。
- 规则按任务选择，不向每个请求重复注入完整规则集。
- 长局上下文必须有确定性的预算和保留策略；不得通过额外 LLM 总结引入新的上帝视角或不可复现状态。

### R5. 发言质量契约

- 每种发言任务定义最低有效贡献，禁止只复述阶段信息或人物设定。
- 首位白天发言在缺少他人发言时，应明确不确定性，并提供至少一个观察框架、关注点或暂定策略；不得编造玩家行为。
- 后续白天发言应回应至少一条已有公开主张，并形成当前立场或待验证问题。
- 狼队策略和意见必须直接完成队内协作目标；遗言和 PK 发言必须分别围绕最终信息交付和生存辩护展开。
- 发言不得把玩家的公开陈述自动当作事实，不得生成没有来源的概率、行为或夜间结果。

### R6. 行动质量与合法性契约

- 本任务明确包含为保证 Prompt 输入正确所必需的候选范围、弃票规则、投票披露时机、历史查验和女巫同夜用药契约修正，不把这些问题留作纯文案之外的后续工作。
- 所有候选项同时展示稳定 `playerId`、座位号和姓名；返回值使用稳定 `playerId`。
- 候选列表必须与最终校验共享同一个规则计算结果，不能由 Prompt 和解析器各自计算。
- 完全对称的首夜选择允许明确承认“没有差异化信息”，并采用可复现且不固定偏向列表首项的中立打破平局方法。
- 女巫行动必须显式包含药品库存、当夜另一瓶药状态和相关用药限制。
- 白天放逐与 PK 投票必须使用不同任务规格、不同候选范围和正确的弃票规则。
- 密封选择继续保持 `host_only`，不得通过 Prompt 字符串过滤替代事件可见性。

### R7. 输出协议与失败恢复

- Prompt 版本升级为 v2，并使用与输出形态匹配的 schema 名称。
- 用简短 `decisionSummary` 替代泛化 `reasoning`；它只记录引用的事实、关键权衡和最终意图，不要求详细思维链，也不评价人设或写作风格。
- 玩家可见内容与调试元数据必须分字段；只有 `text` 写入发言事件。
- JSON、必填字段和目标合法性仍由程序校验。对于可修复的 JSON/候选错误，允许一次最小化修复请求；修复仍失败时保持 Draft 不变并记录失败。
- 历史 v1 GenerationRecord 和旧游戏快照继续可读，不做破坏性数据迁移。

### R8. 可验证性

- 结构测试覆盖全部 12 种任务，而不只断言存在通用短语。
- `docs/examples/` 暴露的失败模式形成回归场景。
- 必须保留并扩展私密事件的负向可见性测试、行动合法性测试和 GenerationRecord 调试信息。
- 提供使用同一局面重放 Prompt v1/v2 的人工评估清单，至少评价：场景正确、事实一致、信息边界、任务完成、策略价值、自然度和结构合法性。

## Acceptance Criteria

- [x] 代码中全部 12 种 LLM Draft 都有独立且穷举的任务规格；非 LLM Draft 不会误触发生成。
- [x] 每个请求的开头明确当前时间、场景、频道、听众、允许披露范围和尚未发生的关键步骤。
- [x] Prompt 清楚分开确认事实、私有事实、公开主张、阵营讨论和未知信息。
- [x] `wolf_opinion_given` 不会误称白天，不会对狼队友隐藏狼人身份，并明确回应已有战术、主目标和备选方向。
- [x] `wolf_strategy_given` 在首夜无证据时不编造座位特征或错误概率，并明确主要方案、备选方案和白天伪装方向。
- [x] `day_speech_given` 的首位玩家产生至少一个有效观察框架；后续玩家回应已有发言并给出一致立场。
- [x] 神职公开发言不会同时声明确定查验结果和与该结果冲突的身份判断。
- [x] 狼人公开发言不会直接泄露狼队友、私聊、刀口或密票来源。
- [x] `last_words_given` 和 `pk_speech_given` 分别围绕遗言交付和 PK 辩护生成，不再表现为普通白天发言。
- [x] 守卫 Prompt 包含上夜守护目标和本夜合法候选；不声称知道狼刀目标。
- [x] 狼人密票只看到允许的团队讨论，不看到较早的密封票；生成目标属于共享合法候选。
- [x] 预言家 Prompt 包含历史查验结果，默认不重复查验，并在首夜对称局面诚实说明中立选择。
- [x] 女巫解药区分规则可推出的非狼人阵营与不可推出的具体平民/神职身份；解药和毒药 Prompt 都包含真实库存及同夜用药状态。
- [x] 猎人 Prompt 明确可开枪的死亡触发原因和存活候选。
- [x] 放逐投票和 PK 投票只显示各自合法候选，并按规则决定是否允许 `null` 弃票。
- [x] `voteReveal=after_all_votes` 时，后续投票者的 LLM 上下文看不到尚未统一公开的单票。
- [x] 输出使用 `decisionSummary`，不再要求模型输出或保存详细思维链/人设自评。
- [x] 非法 JSON 或非法目标至多触发一次约束明确的修复；失败不会修改 Draft。
- [x] v1 历史记录、旧游戏 Prompt 快照和编辑器中的 GenerationRecord 展示保持兼容。
- [x] 全部相关单元测试、类型检查和生产构建通过，并完成人工 v1/v2 回放评估（项目没有 lint script）。

## Out of Scope

- 新增狼人杀角色、警长流程或改变胜负规则。
- 用额外 LLM 调用持续总结整局历史或建立长期记忆。
- 让模型绕过现有事件确认、服务端角色校验或合法目标校验。
- 在本任务中重写主持人播报、Preview 或音频系统。
- 以多代理辩论或两阶段模型链替代当前“一次生成一个 Draft”的主流程；一次失败修复请求除外。
