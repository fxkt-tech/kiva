# 近战扫掠判定与离线烘焙

父任务：`11-12-hit-detection`，设计见父任务 design.md §2、§3。依赖 `11-12-anim-sim-clock`。

## Goal

所有近战命中由刀刃实际扫过的体积决定，判定数据从动画离线烘焙，改招式只需重新烘焙。

## Requirements

| ID | 需求 |
|---|---|
| R1 | `make bake-hits` 生成 `src/simulation/combat/hit_tracks.rs`：每个 `TrackId` 的逐 tick 刀刃线段、有效窗口、刀刃半径、最远距离 |
| R2 | 过期校验测试：重新烘焙结果与已提交数据不一致时失败，并提示运行烘焙命令 |
| R3 | 玩家普攻、玩家范围技的刀刃部分、Boss、普通敌人统一使用逐 tick 扫掠，与目标物理胶囊相交检测；有效窗口内每个目标每段只命中一次；墙体遮挡接触点时不算命中 |
| R4 | 删除手写的近战距离、角度、命中时刻常量（`MeleeProfile.range/hit_time`、`MELEE_ARC`、Boss `HIT_*`/`ACTIVE`）；范围技的冲击时刻取自烘焙数据 |
| R5 | 命中事件的位置是实际接触点；防御、能量、耐久、事件归属不变 |
| R6 | 开发热键切换判定调试显示（扫掠线段、受击胶囊、接触点），默认关闭 |

## Acceptance Criteria

- [ ] 无窗口测试：刀刃扫过的目标被命中；正前方但刀没扫到的目标（例如挥击另一侧、超出刀尖）不被命中
- [ ] 高速挥击不漏检（插值测试）；多窗口招式在每个窗口各命中一次；隔墙不命中
- [ ] 蹲伏目标的受击体变矮
- [ ] Boss 回归更新为读取烘焙窗口后通过；防御顺序测试通过
- [ ] 过期校验测试通过，并且 `make bake-hits` 结果可复现
- [ ] `make check`、WASM Clippy 通过
