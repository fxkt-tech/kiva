# 近战扫掠判定与离线烘焙

父任务：`11-12-hit-detection`，设计见父任务 design.md §2、§3。依赖 `11-12-anim-sim-clock`。

## Goal

所有近战命中由刀刃实际扫过的体积决定，判定数据从动画离线烘焙，改招式只需重新烘焙。

## Requirements

| ID | 需求 |
|---|---|
| R1 | `make bake-hits` 生成 `src/simulation/combat/hit_tracks.rs`：每个 `TrackId` 的逐 tick 刀刃线段、有效窗口、刀刃半径、最远距离 |
| R2 | 过期校验测试：重新烘焙结果与已提交数据不一致时失败，并提示运行烘焙命令 |
| R3 | 玩家普攻、玩家范围技的刀刃部分、Boss、普通敌人统一使用逐 tick 扫掠，与目标物理胶囊相交检测；每个动作对每个目标只命中一次；墙体遮挡接触点时不算命中 |
| R4 | 删除手写的近战距离、角度、命中时刻常量（`MeleeProfile.range/hit_time`、`MELEE_ARC`、Boss `HIT_*`/`ACTIVE`）；范围技的冲击时刻取自烘焙数据 |
| R5 | 命中事件的位置是实际接触点；防御、能量、耐久、事件归属不变 |
| R6 | 开发热键切换判定调试显示（扫掠线段、受击胶囊、接触点），默认关闭 |

## Acceptance Criteria

- [x] 无窗口测试：刀刃扫过的目标被命中；正前方但刀没扫到的目标（例如挥击另一侧、超出刀尖）不被命中
- [x] 高速挥击不漏检（插值测试）；隔墙不命中。多窗口招式改为每个动作对每个目标只命中一次（见父任务 design.md 的修订）
- [x] 蹲伏目标的受击体变矮
- [x] Boss 回归更新为读取烘焙窗口后通过；防御顺序测试通过
- [x] 过期校验测试通过，并且 `make bake-hits` 结果可复现
- [x] `make check`、WASM Clippy 通过

- 过期校验做过变异验证：把 Boss 第一招的片段映射改一个数，`hit_tracks_match_animation` 失败并提示重新烘焙。

## 烘焙结果

| 招式 | 有效窗口（tick） | 正前方够到的距离 |
|---|---|---|
| 锤 普攻 1／2／3 | 6–9／6–19／14–23 | 约 2.0／1.6／1.5m |
| 链斧 普攻 1／2／3 | 5–6／5–13／10–16 | 约 1.9／1.6／1.5m |
| 锤 E／链斧 E 的刀刃 | 8–9／20–22 | 冲击范围不变（3m） |
| Boss 1／2／3 | 44–49／44–57、60–67／44–52、55–58 | 约 2.4／2.0／1.9m |
| 普通敌人 | 26–33、37–46 | 约 1.5m |

“够到的距离”含目标半径 0.35m，按最终烘焙数据对正前方站立目标实测；窗口随动画变化，以 `make bake-hits` 的输出为准。
